1OPTIC FLOW Ch.2 · Horn–Schunck13 pts

Question. You have a semantic-segmentation network: image $I\!\to\!$ label map $S$ (each pixel a class $0..c\!-\!1$; all cars share one label, etc.). Modify Horn–Schunck to take $I_1,I_2$ and their label maps $S_1,S_2$ and output the optic flow.

How I thought about it

Base Horn–Schunck is $$\min_{u,v}\iint (I_xu+I_yv+I_t)^2+\alpha(|\nabla u|^2+|\nabla v|^2)\,dx\,dy.$$ Its one well-known weakness (Ch.2): the smoothness term smooths flow everywhere, so it blurs motion across object boundaries — a car edge against the road gets a smeared, averaged flow. The extra input $S$ is exactly a boundary detector: wherever the label changes, there is a real object boundary where the flow is allowed to jump. So the modification writes itself: keep the data term, but stop the smoothness term from diffusing flow across label boundaries.

Solution

Introduce a per-edge weight that is on inside a class and off across classes. For neighbouring pixels $p,q$: $$w(p,q)=\begin{cases}1 & S_1(p)=S_1(q)\\ \varepsilon\approx0 & S_1(p)\neq S_1(q)\end{cases}$$ and minimise the segmentation-aware energy $$\min_{u,v}\iint (I_xu+I_yv+I_t)^2+\alpha\,w(x)\big(|\nabla u|^2+|\nabla v|^2\big)\,dx\,dy.$$ Following the same Euler–Lagrange derivation as in Ch.2, the ordinary Laplacian $u_{xx}+u_{yy}$ is replaced by a weighted graph Laplacian: each neighbour contributes $-w(p,q)$ instead of $-1$, and the diagonal is the sum of incident weights. Edges that cross a label boundary have weight $0$, so flow no longer leaks across the boundary — you get sharp motion discontinuities exactly at object silhouettes. The linear system stays sparse and is solved iteratively exactly as before.

Using both frames' labels. $S_2$ gives a second, optional constraint: a correctly-tracked pixel should land on a pixel of the same class, so add a soft data term $\lambda\big(S_2(x+u,y+v)\neq S_1(x)\big)$ (penalise flow that sends a "car" pixel onto a "road" pixel). Because all instances of a class share the label, this is a soft consistency prior, not a per-instance match.

Answer in one line: Horn–Schunck with a label-gated smoothness weight ($w=0$ across label changes) → boundary-preserving dense flow; optionally a label-consistency data term using $S_2$.
2TRACKING — loaded die Ch.4 · Condensation resampling12 pts

Question. Simulate rolling a loaded six-sided die with probabilities $(p_1,\dots,p_6)$, using only $\texttt{rand()}\sim U[0,1]$.

How I thought about it

This is literally the "select" step of the Condensation / particle-filter algorithm in Ch.4, which samples a particle index in proportion to its weight using one uniform draw. The die faces are the particles; $p_i$ are the weights. So I just reuse that trick.

Solution

Build the cumulative distribution (CDF): $$C_0=0,\qquad C_i=C_{i-1}+p_i\quad(i=1..6),\qquad C_6=1.$$ Then:

1. Draw $r=\texttt{rand()}\in[0,1]$.
2. Return the smallest $j$ such that $C_j>r$ (equivalently the $j$ with $C_{j-1}\le r

Face $j$ is returned whenever $r$ lands in the interval $[C_{j-1},C_j)$, whose length is exactly $p_j$; since $r$ is uniform, $P(\text{face }j)=p_j$. This is the exact wording of the Condensation select step in Ch.4: "generate $r\in[0,1]$; find smallest $j$ with $C^{(j)}_{t-1}>r$." Cost $O(\log 6)$ with binary search on $C$ (trivial here).

Answer: Inverse-CDF sampling — cumulative sums $C_i$, one uniform $r$, pick the bin $r$ falls into. Same as particle-filter resampling.
3INTRINSIC IMAGES — online reflectance Ch.12 · Weiss median13 pts

Question. Give an online algorithm for the reflectance image $R_t$ from a stream $I_1,\dots,I_t$. You may store at most 256 images (or equivalent memory). Hint: pixel intensities are in $[0,255]$.

How I thought about it

Ch.12 (Weiss): under $I(x,t)=R(x)\,L(x,t)$, in the log domain $i=r+l$. Filter each frame with derivative filters $f_n$; assuming the filtered illumination is sparse, the ML estimate of the filtered reflectance is the per-pixel temporal median of the filtered frames, $\hat r_n(x)=\operatorname{median}_t\, (f_n\!*\!i)(x,t)$, and $r$ is then reconstructed from the $\hat r_n$ by the fixed pseudo-inverse (eq. 6 in Ch.12), $R=e^{r}$. The only thing blocking an online implementation is the median, which normally needs all frames in memory. The hint "$[0,255]$" and "store 256 images" is the giveaway: a value with 256 possible levels has a running median computable from a 256-bin histogram.

Solution

Keep, for every pixel and every filter $f_n$, a histogram with 256 bins over the (quantised) filter-response range. This costs 256 numbers per pixel — the "256 images" budget — and is independent of $t$, so the stream can be arbitrarily long.

For each new frame $I_t$:

1. Compute $i=\log I_t$ and the filter responses $f_n*i$.
2. For each pixel, increment the histogram bin of its response ($O(1)$).
3. Running median $\hat r_n(x)$ = smallest bin $b$ whose cumulative count reaches $t/2$ (one pass over 256 bins, or maintained incrementally).
4. Reconstruct $R_t$ from the current medians with the fixed deconvolution filter $g$ (eq. 6–7 of Ch.12 — $g$ depends only on the filters, precomputed once).

Memory = $256\times(\#\text{filters})$ per pixel ≈ the allowed budget; per-frame work is $O(1)$ per pixel. Every frame you can emit an updated reflectance $R_t$. (Weiss uses just horizontal + vertical derivatives, so only two histograms per pixel are needed.)

Answer: Per-pixel 256-bin histogram of the filtered log-frames → running temporal median → Weiss reconstruction. Constant memory, $O(1)$/pixel/frame, truly online.
4EVOLVING TIME FRONTS — Iguazu not in Book 212 pts

Question. A video pans left→right over the Iguazu waterfalls. Synthesize a video that pans right→left while the water still falls downward. ("Appeared in the paper discussed in class.")

Honesty note Book 2 has no chapter on this (it is the "dynamosaicing / evolving time fronts" paper). The answer below uses only the space-time reasoning the book does support; the specific named technique is outside Book 2.
How I thought about it

Two motions are entangled in the clip: the camera pan (global, horizontal) and the water (local, downward, a dynamic texture — cf. Ch.5). Reversing playback would reverse both (water would flow up), which is wrong. So the two must be decoupled: reverse the spatial scan direction while keeping local time moving forward.

Solution (space-time volume)

Stack all frames into an $x\!-\!y\!-\!t$ volume. An ordinary output frame is a planar slice at $t=\text{const}$ (a "time front"). The horizontal pan means: as the original scan advances in time, the front reveals columns from left to right.

To pan right→left with water still falling, sweep a slanted / evolving time-front surface through the volume that moves across $x$ in the opposite direction to the original scan, but where, along the sweep, the local time coordinate still increases. Each output frame is the image obtained by cutting the volume with this surface; advancing the surface in $-x$ generates the reversed camera pan. Because within every cut the local $t$ only moves forward, the falling water (the dynamic texture) keeps playing forward and falls down normally. In short: reverse the spatial component of the cutting surface, keep its temporal component forward.

Answer: Build the $x\,y\,t$ volume; synthesize each output frame as a non-planar time-front cut; sweep the front in reverse-$x$ while local time advances forward — pan reverses, water still falls. (Technique itself is outside Book 2.)
5CLONE DETECTION Ch.11 · PatchMatch13 pts

Question. An object was removed by inpainting/cloning. Given only the doctored image, automatically detect the cloned regions (the two dark blobs of the answer mask).

How I thought about it

Cloning means two regions of the same image are near-identical copies. Ch.11's PatchMatch computes, for every patch, its nearest-neighbour patch elsewhere — and its key property is that a coherent region produces a constant offset in the nearest-neighbour field $f(x)$. A copied block is precisely a region whose patches all match another location with (a) almost-zero patch distance and (b) one shared offset. So: run PatchMatch of the image against itself.

Solution

1. Run PatchMatch with source = target = the input image, producing the offset field $f(x)$ and match distance $d(x)=\|P_x-Q_{x+f(x)}\|^2$. Exclude the trivial match: forbid offsets smaller than a few patch-widths, so a patch cannot match itself/its immediate neighbours.
2. A pixel is a clone candidate when $d(x)\approx 0$ (near-identical copy).
3. Among candidates, keep those whose offset $f(x)$ agrees over a connected region — i.e. histogram the offsets and keep large connected components sharing one dominant offset $v$. A genuine copy-move produces a matched pair: region $A$ with offset $+v$ and region $B$ with offset $-v$.
4. Output those connected components as the clone mask.

The random-search + propagation core of PatchMatch makes this real-time; the "constant-offset coherent region" is exactly what distinguishes a real clone from accidental patch similarity.

Answer: Self-PatchMatch (image vs itself, trivial match excluded) → flag regions with near-zero patch distance and a shared coherent offset → those matched connected components are the clones.
6GEODESIC DISTANCE — the $\gamma$ parameter Ch.9/10 · geodesic12 pts

Question. With $d(a,b)=\inf_\Gamma\int_0^{l(\Gamma)}\sqrt{1+\gamma^2(\nabla I(s)\cdot\Gamma'(s))^2}\,ds$, decide for maps (c) and (d) whether $\gamma=0$ or $\gamma>0$ (darker = shorter). Explain.

How I thought about it

$\gamma$ is the knob that decides how much the image influences distance (same idea as the edge weights in Ch.9/10). Look at the integrand:

  • $\gamma=0$: integrand $=\sqrt{1}=1$, so $d=\int ds=$ pure arc length. The distance is purely spatial/Euclidean from the object region $\Omega$ and completely image-blind. The map is a smooth halo expanding uniformly from the silhouette; the background swirls / textures leave no trace.
  • $\gamma>0$: the term $\gamma^2(\nabla I\cdot\Gamma')^2$ adds cost wherever a path runs across an image gradient. Distance becomes image-aware: it grows fast when crossing edges and stays small inside homogeneous regions, so the image structure (the background swirls, the boy's outline) becomes visible in the distance map, and the map "sticks" at edges.
Determination

Using the visual cue "does the map show the image's own structure?":

(c) — smooth halo, background swirls invisible ⇒ $\gamma=0$ (Euclidean, geometry only).
(d) — the swirl textures / edges show up in the field ⇒ $\gamma>0$ (image gradients cost extra, so distance jumps at those structures).

Answer: (c) uses $\gamma=0$ (image-blind Euclidean halo); (d) uses $\gamma>0$ (edges visible because crossing them costs distance). Rule: if the map ignores image texture it's $\gamma=0$; if the texture prints through, it's $\gamma>0$.
7SEGMENTATION — 3D point cloud + scribbles Ch.9 · geodesic propagation13 pts

Question. Given an unordered 3D point cloud and coloured user scribbles (diamonds), reproduce the right-hand segmentation.

How I thought about it

This is the colorization/matting idea (Ch.9/10) — propagate a few seed labels by geodesic distance — but the domain is a point cloud, not a pixel grid. The only new work is building the right graph; then the same Dijkstra machinery applies.

Solution

1. Build a graph $G=(V,E)$: nodes = the 3D points. Since the list is unordered, connect each point to its $k$ nearest neighbours in 3D (kNN), giving a local mesh.
2. Edge weights so that distance grows across real object boundaries: $w(p,q)=\|p-q\|$ (Euclidean gap), optionally combined with a surface-normal or local-feature difference so that crossing a sharp geometric boundary is expensive.
3. Seeds $\Omega_k$ = the points carrying scribble colour $k$.
4. For each label $k$, compute the geodesic distance map $D_k(v)=d_L(v,\Omega_k)$ over the graph with Dijkstra (or fast sweeping), exactly as in Ch.9.
5. Assign each point the nearest seed's label: $\text{label}(v)=\arg\min_k D_k(v)$. The boundary is where two $D_k$ tie. This yields the coloured segmentation on the right.

Answer: kNN graph on the points → edge weights from 3D/normal dissimilarity → per-scribble geodesic distance (Dijkstra) → label each point by its nearest scribble. Ch.9's colorization, moved from a pixel grid to a point graph.
8BIDIRECTIONAL SIMILARITY — is $D$ symmetric? Ch.11 · completeness–coherence12 pts

Question. $D(P,Q)=\max_{p\in P}\min_{q\in Q}d(p,q)$. Is $D(P,Q)=D(Q,P)$? Prove or give a counter-example.

How I thought about it

This is the directed (one-sided) distance — it is exactly $D_{\text{com}}$ vs $D_{\text{coh}}$ from Ch.11: measuring $P\!\to\!Q$ is not the same as $Q\!\to\!P$. That asymmetry is precisely why retargeting needs both terms. So I expect "not symmetric" and just need a two-point counter-example.

Solution — counter-example

Take on the real line $P=\{0\}$ and $Q=\{0,10\}$.

$D(P,Q)=\max_{p\in P}\min_{q\in Q}d(p,q)=\min\{d(0,0),d(0,10)\}=0.$
$D(Q,P)=\max_{q\in Q}\min_{p\in P}d(q,p)=\max\{\,d(0,0),\,d(10,0)\,\}=\max\{0,10\}=10.$

Since $0\neq 10$, $D(P,Q)\neq D(Q,P)$ — $D$ is not symmetric.

Answer: No. Counter-example $P=\{0\},Q=\{0,10\}$ gives $D(P,Q)=0$ but $D(Q,P)=10$. This is the completeness-vs-coherence asymmetry from Ch.11, which is why the retargeting loss symmetrises it as $\alpha D_{\text{com}}+(1-\alpha)D_{\text{coh}}$.

Exam 2 — Moed B (1/8/2022)

1OPTIC FLOW — sparse LiDAR depth Ch.2 · Horn–Schunck13 pts

Question. A car has a grayscale camera and a LiDAR giving depth at a sparse set of pixels. Modify Horn–Schunck to use $I_1,I_2$ and sparse depth maps $D_1,D_2$ and output the flow.

How I thought about it

Same weakness as before: HS over-smooths across object boundaries. Depth gives two useful signals. (1) Depth discontinuities are object boundaries — flow may jump there, so smoothness should switch off across depth jumps. (2) Where depth exists it is a hard extra constraint anchoring the flow. Because LiDAR is sparse, both effects only act at the pixels that have a depth value.

Solution

Depth-aware smoothness. For neighbours $p,q$ that both have depth, set the smoothness weight $w(p,q)=\exp\!\big(-(D_1(p)-D_1(q))^2/2\sigma_d^2\big)$ — near 1 within a surface, near 0 across a depth edge. Where depth is missing, fall back to the plain constant $\alpha$ (or an intensity-based weight). Minimise $$\iint (I_xu+I_yv+I_t)^2+\alpha\,w(x)\big(|\nabla u|^2+|\nabla v|^2\big)\,dx\,dy,$$ which (as in Moed A Q1) becomes a weighted-Laplacian sparse solve that preserves motion boundaries at depth edges.

Sparse depth-constancy data term. Only at pixels where LiDAR is available, a correctly tracked pixel should carry its depth to the matching pixel (up to camera egomotion), so add $\;\lambda\sum_{x\in\text{LiDAR}}\big(D_2(x+u,y+v)-D_1(x)\big)^2.$ This pins the flow at the sparse measured points and lets the smoothness term interpolate it to the rest — the same "few reliable anchors + smoothness fills in" structure the book uses repeatedly.

Answer: HS with (i) smoothness weight small across depth discontinuities and (ii) a sparse depth-constancy data term at LiDAR pixels. Sparse anchors + boundary-aware smoothness.
2TRACKING — the Bayes recursion Ch.4 · particle filter12 pts

Question. State the Markov and conditional-independence assumptions and show $p(x_{1:t}\mid z_{1:t})\propto p(z_t\mid x_t)\,p(x_t\mid x_{t-1})\,p(x_{1:t-1}\mid z_{1:t-1}).$

How I thought about it

This is the derivation in Ch.4. Start from Bayes, then use the two assumptions to peel one time step off the front so the rest collapses back into the same posterior at $t\!-\!1$ (a recursion).

Assumptions

Markov model (motion): $\;p(x_t\mid x_{1:t-1})=p(x_t\mid x_{t-1})\;\Rightarrow\; p(x_{1:t})=p(x_t\mid x_{t-1})\,p(x_{1:t-1}).$
Conditional independence of observations: $\;p(z_{1:t}\mid x_{1:t})=p(z_t\mid x_t)\,p(z_{1:t-1}\mid x_{1:t-1})=\prod_{\tau=1}^{t}p(z_\tau\mid x_\tau).$

Derivation

$$p(x_{1:t}\mid z_{1:t})=\frac{p(z_{1:t}\mid x_{1:t})\,p(x_{1:t})}{p(z_{1:t})}\;\propto\;p(z_{1:t}\mid x_{1:t})\,p(x_{1:t}).$$ Insert both assumptions: $$=\underbrace{p(z_t\mid x_t)\,p(z_{1:t-1}\mid x_{1:t-1})}_{\text{cond. indep.}}\;\cdot\; \underbrace{p(x_t\mid x_{t-1})\,p(x_{1:t-1})}_{\text{Markov}}.$$ Regroup the two $t\!-\!1$ factors: $$=p(z_t\mid x_t)\,p(x_t\mid x_{t-1})\,\underbrace{\big[p(z_{1:t-1}\mid x_{1:t-1})\,p(x_{1:t-1})\big]}_{\propto\;p(x_{1:t-1}\mid z_{1:t-1})}.$$ The bracket is (again by Bayes at $t\!-\!1$) proportional to $p(x_{1:t-1}\mid z_{1:t-1})$, giving $$\boxed{\,p(x_{1:t}\mid z_{1:t})\propto p(z_t\mid x_t)\,p(x_t\mid x_{t-1})\,p(x_{1:t-1}\mid z_{1:t-1}).\,}$$ The three factors are the likelihood, the motion model, and the recursion — the basis of the particle filter.

3DYNAMIC TEXTURE — Word2Vec text synthesis Ch.5 · state-space texture13 pts

Question. Word2Vec maps words to vectors. Use it to synthesize text: short input text → a page of output text.

How I thought about it

The slot is "dynamic texture," so map it onto Ch.5: a texture is a low-dimensional linear state-space process driven by noise, whose parameters are learned from a sample and then run forward to generate novel output. In Ch.5 a frame becomes a vector via SVD; here a word already becomes a vector via Word2Vec. So the word sequence is a trajectory in embedding space, and text synthesis = drive that trajectory forward with noise, then decode vectors back to words.

Solution

1. Vectorise. Turn the input text into the vector sequence $y_1,\dots,y_T$, $y_t=\text{W2V}(\text{word}_t)$ — the analogue of Ch.5's "frame → vector."
2. System identification. Model it as the Ch.5 dynamical system $x_{t+1}=Ax_t+Bv$, $y_t=Cx_t+w$. Because embeddings are already a Euclidean space, take $x_t=y_t$ (optionally reduce dimension with SVD as in Ch.5) and fit the auto-regression by least squares, $\hat A=\arg\min_A\sum_t\|x_{t+1}-Ax_t\|^2$ (or a higher-order ARMA $x_t=\sum_i p_i x_{t-i}+\varepsilon$).
3. Generate. Seed with the last state(s) of the input and iterate $x_{t+1}=\hat Ax_t+Bv$ for a page's worth of steps. The noise $v$ is essential (Ch.5): without it the trajectory is deterministic and dies/repeats; with it the "text texture" keeps exploring.
4. Decode. Map each synthesized vector back to a word by nearest neighbour in the vocabulary, $\text{word}=\arg\min_{w}\|x-\text{W2V}(w)\|$. Emit the word stream.

Like all dynamic-texture synthesis, this reproduces local statistics/style, not deep grammar — the same limitation Ch.5 notes for object-textures.

Answer: Treat the Word2Vec-vector sequence as a dynamic texture: fit an ARMA/linear state-space model (Ch.5), run it forward with noise, decode each generated vector to its nearest word.
4LIGHT FIELDS — novel view from a rotating camera not in Book 212 pts

Question. A camera on a rotating arm records a video around an axis. Synthesize a novel view from a virtual camera inside the circle.

Honesty note Book 2 has no light-fields chapter. The answer uses only the multi-view geometry the book supports (Ch.1 projection/homography) plus interpolation; the named "light field / concentric mosaic" method is outside Book 2.
How I thought about it

The rotating camera samples a dense 1-parameter family of views of the scene — i.e. a big set of recorded rays. A "novel view" is just a new bundle of rays through the virtual camera's centre. If for each virtual ray I can find the recorded ray that coincides with it, I can copy that pixel. This is ray re-indexing + interpolation, built on the projection matrix of Ch.1.

Solution

1. Calibrate. For every recorded frame $k$ know its projection matrix $P_k$ (Ch.1: intrinsics + the known arm angle/position give $R_k,t_k$). Give the virtual camera its own $P_v$.
2. Per virtual pixel = a ray. Each pixel of the virtual view back-projects (via $P_v$) to a 3D ray.
3. Find the matching recorded ray. Among all frames, find the camera/pixel whose optical ray best coincides with that virtual ray (same line in space through the scene). Sample that pixel's colour.
4. Interpolate. When a virtual ray falls between two recorded rays, linearly blend the nearest recorded samples (weighted by angular closeness), so the synthesized view is smooth.
Assemble all virtual pixels → the novel view. (For scene points at unknown depth, the recorded ring of views densely covers ray-space, so nearby recorded rays give a good approximation — this is the light-field/IBR idea.)

Answer: Reconstruct each virtual pixel by finding the recorded camera ray that coincides with the virtual ray (via the Ch.1 projection matrices) and interpolating between the nearest recorded views. (Light fields as a named topic are outside Book 2.)
5PATCHMATCH — extend to k-NN Ch.11 · PatchMatch13 pts

Question. 1-NN PatchMatch returns the single best match per patch. Extend it to k-NN: the top-$k$ nearest neighbours per patch.

How I thought about it

Everything in PatchMatch (Ch.11) is "keep the best offset; improve it by propagation + random search." For k-NN, just keep the best $k$ offsets instead of one, and let both operations draw candidates from the neighbours' whole $k$-lists. The data structure per patch becomes a bounded heap of size $k$.

Solution

Per patch $x$ maintain a size-$k$ max-heap of offsets ordered by patch distance (top = current worst of the $k$).

1. Init: $k$ random distinct offsets per patch, with their distances.
2. Propagation (alternating raster scans): candidate pool = $x$'s current $k$ offsets $\cup$ the $k$ offsets of the left neighbour $\cup$ the $k$ of the neighbour above. Keep the $k$ smallest-distance distinct offsets.
3. Random search: around each held offset (or the best), sample with geometrically shrinking radius; if a sample beats the current worst (heap top) and is not a near-duplicate of an offset already held, insert it and evict the worst.
4. Iterate 4–6 passes to convergence; output each patch's $k$-offset list.

Distinctness is the one subtlety: reject candidates too close to already-held offsets, otherwise the heap fills with $k$ copies of the same match. Cost is the 1-NN cost times ~$k$; propagation still exploits spatial coherence, so it stays far cheaper than brute force.

Answer: Replace the single best offset with a size-$k$ heap; propagation and random search draw from neighbours' full $k$-lists and keep the $k$ best distinct offsets.
6GEODESIC DISTANCE — path along Lena's hat edge Ch.9 · Dijkstra12 pts

Question. The user clicks points $A$ and $B$; the system auto-draws the path between them that follows the edge of the hat. Compute that path.

How I thought about it

"Follows the edge" = a shortest path in a weighted grid, i.e. Ch.9's geodesic-distance machinery. But note the sign flip: colorization made crossing an edge expensive (weight $=|\nabla Y|$) so paths avoid edges. Here we want the path to ride the edge, so it must be cheap to travel where the gradient is strong — the weight is inversely related to gradient magnitude.

Solution

1. Build the pixel grid graph. For an edge between neighbours, set a weight that is small on strong image edges, e.g. $\;w=\dfrac{1}{|\nabla I|+\varepsilon}\;$ or $\;w=\big(\max|\nabla I|-|\nabla I|\big)$. Walking along a high-gradient contour (the hat rim) costs almost nothing; wandering into flat regions is expensive.
2. Run Dijkstra from $A$; read off the shortest path to $B$ (Ch.9's Bellman/DP shortest path). The min-cost path hugs the hat's edge, reproducing the black curve.
3. Draw it. (This is the "intelligent scissors" use of geodesic distance — same algorithm as colorization, with edge-following weights instead of edge-avoiding.)

Answer: Grid graph with weights small where $|\nabla I|$ is large (edge-following), then Dijkstra shortest path $A\!\to\!B$. Same machinery as Ch.9, inverted edge cost.
7SEGMENTATION — social network interest mix Ch.9 · geodesic blending13 pts

Question. A graph $G=(V,E)$ with tie strengths $w(u,v)$; a few users are labelled (finance expert $u_1$, fashion expert $u_2$). Learn every node's mix of interests (e.g. 30% finance / 70% fashion).

How I thought about it

Labelled experts = scribbles; the wanted output is a soft mixture that sums to 1, which is exactly the blending formula from colorization (Ch.9), not a hard label. The graph is already given, so I only convert tie strength into a distance and reuse geodesic distance + the soft blend.

Solution

1. Strength → distance. A strong tie should mean "close," so set edge length $\ell(u,v)=1/w(u,v)$ (or $-\log w$). Geodesic distance is then short along chains of strong connections.
2. Seeds $\Omega_k$ = the users labelled with interest $k$.
3. Distance maps. Compute $D_k(v)=$ geodesic distance from every node $v$ to seed set $k$ with Dijkstra on $G$.
4. Soft mixture via the Ch.9 blend, $W(D)=1/D^b$: $$\text{interest}_k(v)=\frac{W(D_k(v))}{\sum_j W(D_j(v))}.$$ These weights are non-negative and sum to 1, giving each node its percentage split (e.g. 0.30 finance / 0.70 fashion). This is literally colorization's $c(x)=\dfrac{\sum_k W(D_k)c_k}{\sum_k W(D_k)}$ with categories in place of colours and the normalized weights read out as the interest mix.

Answer: Turn tie strength into edge length $1/w$, compute geodesic distance from each labelled expert, and output the distance-weighted normalized blend $W(D_k)/\sum_j W(D_j)$ as each node's interest percentages.
8CLUSTERING — does k-means terminate? Ch.6 · k-means12 pts

Question. Is k-means guaranteed to terminate? Explain.

How I thought about it

Ch.6 defines k-means as minimising the distortion $J=\sum_i\|x_i-c_{\text{enc}(i)}\|^2$ by alternating two steps. If I can show each step never increases $J$ and that only finitely many configurations exist, termination follows.

Argument

Both steps are non-increasing in $J$:

• Assignment step (assign each $x_i$ to its nearest centre): by definition of "nearest," each point's contribution $\|x_i-c\|^2$ can only stay the same or drop. So $J$ does not increase.
• Update step (each centre ← mean of its members): the mean minimises $\sum_{i\in S_j}\|x_i-c\|^2$ (setting the derivative to $0$ gives $c_j=\frac1{|S_j|}\sum_{i\in S_j}x_i$, Ch.6). So $J$ does not increase.

Therefore $J$ is monotonically non-increasing over iterations.

Finiteness: there are only finitely many ways to assign $n$ points to $k$ clusters (at most $k^n$). Each distinct assignment fixes its centres (the means) and hence a specific value of $J$. Because $J$ never increases, once the algorithm leaves an assignment (which happens only when the assignment strictly lowers $J$, using a fixed tie-break rule) it can never return to it — that would require $J$ to go back up. A monotone sequence over a finite set of values cannot decrease forever, so the assignment must stop changing after finitely many steps, at which point the algorithm halts.

Answer: Yes. Distortion decreases (never increases) at every step and there are only finitely many assignments, so no assignment can repeat and the algorithm must stop in finite time. Caveat: it converges to a local minimum (global k-means is NP-hard) and the result depends on initialization — but termination is guaranteed.

Four meta-recipes that solve almost all of them

  • "Modify algorithm A to accept new input B." Find where $B$ signals a boundary or a reliable measurement. Inject it as a smoothness weight (turn smoothing off across $B$'s boundaries) and/or an extra data term (anchor the solution where $B$ is measured). — Optic-flow slot, every time.
  • "Design an online / efficient version." Replace "store everything" with a running statistic: a per-pixel histogram (running median/mode), a low-rank factorization, or PatchMatch instead of brute-force NN.
  • "Adapt an image method to a new domain" (3D points, a graph, words). Build the right graph or vector space, then reuse the same machinery — geodesic distance (Dijkstra), ARMA state-space, or the NN-field — unchanged.
  • "Is $X$ guaranteed / symmetric / a metric?" Either a monotone-decrease + finiteness argument (termination), or a tiny two/three-point counter-example (symmetry).

The single unifying hammer the whole course keeps swinging: define a cost, add a boundary-aware regularizer, minimise it iteratively (least squares / Dijkstra-DP / EM-style alternation).

New practice questions (same patterns)

Ten fresh questions built on the templates above, each with a short answer key. Try them before reading the key.

P1Optic Flow — confidence map slot 1

You are given $I_1,I_2$ and a per-pixel confidence map $U(x)\in[0,1]$ (high where the pixel is textured and reliable, low in flat regions). Modify Horn–Schunck to exploit $U$.

Key: Weight the data term by $U$: $\iint U(x)(I_xu+I_yv+I_t)^2+\alpha(|\nabla u|^2+|\nabla v|^2)$. Trust the brightness constraint only where $U$ is high; in low-$U$ (flat/aperture) regions the data term nearly vanishes and the smoothness prior fills flow in from confident neighbours.
P2Optic Flow — external edge map slot 1

Given $I_1,I_2$ and a binary motion-boundary map $B$ from an external detector, modify Horn–Schunck.

Key: Set the smoothness weight $w(p,q)=0$ for neighbour pairs separated by $B$ (and 1 otherwise) → weighted-Laplacian solve that lets flow jump exactly on $B$. Same structure as Moed A Q1 / Moed B Q1.
P3Tracking — sample from a CDF slot 2

Using only $\texttt{rand()}\sim U[0,1]$, draw a sample from a continuous distribution whose CDF $F$ is known.

Key: Inverse-CDF sampling: $r=\texttt{rand()}$, return $F^{-1}(r)$. The discrete loaded-die trick (Moed A Q2) is the special case where $F$ is a step function.
P4Tracking — filtering recursion slot 2

State the Markov and conditional-independence assumptions and derive the filtering recursion $p(x_t\mid z_{1:t})\propto p(z_t\mid x_t)\int p(x_t\mid x_{t-1})\,p(x_{t-1}\mid z_{1:t-1})\,dx_{t-1}.$

Key: Start from Moed B Q2's posterior recursion, then marginalise $x_{1:t-1}$: the integral of $p(x_t\mid x_{t-1})p(x_{t-1}\mid z_{1:t-1})$ is the predicted prior $p(x_t\mid z_{1:t-1})$; multiplying by the likelihood $p(z_t\mid x_t)$ and normalising gives the filter (Ch.4 "filtering" equation).
P5Intrinsic — online temporal mode slot 3

Give an online, bounded-memory algorithm for the per-pixel temporal mode (most common value) of a $[0,255]$ video (useful for background modelling).

Key: Per-pixel 256-bin histogram; increment each frame ($O(1)$); mode $=\arg\max$ bin. Same memory trick as the online-median reflectance (Moed A Q3), read out the peak instead of the median.
P6Dynamic texture — melody synthesis slot 3

You have a note-embedding ("music2vec") mapping musical notes to vectors. Synthesize a long melody from a short one.

Key: Exactly Moed B Q3 with notes instead of words: embed the note sequence, fit an ARMA/linear state-space model (Ch.5), drive it forward with noise, decode each generated vector to its nearest note.
P7PatchMatch — match across many images slot 5

Extend PatchMatch so that, for each source patch, it finds its nearest neighbour across a set of $M$ target images.

Key: Make the offset carry an image index: the match is $(m,y)$ over image $m$ and position $y$. Propagation still borrows neighbours' $(m,y)$; random search perturbs $y$ and occasionally re-rolls $m$. Keep the single best across all $M$. (Generalises Ch.11's reshuffling-from-multiple-sources.)
P8PatchMatch — detect a duplicated video segment slot 5

Detect a looped/duplicated temporal segment inside a single video.

Key: 3D (space-time) self-PatchMatch, excluding the trivial temporal neighbourhood; a duplicated segment appears as a block of voxels with near-zero patch distance and a coherent, constant temporal offset. Same logic as clone detection (Moed A Q5), in the time dimension.
P9Geodesic — stay in the middle of the road slot 6

User clicks two points; draw the path that stays in the middle of a road (avoiding its edges).

Key: The opposite weighting of the Lena-hat question (Moed B Q6): make edges expensive, $w=|\nabla I|$ (the colorization weight), then Dijkstra $A\!\to\!B$. The path avoids high-gradient road boundaries and runs through the smooth interior.
P10Clustering / theory — is k-means monotone? can it cycle? slot 8

Can the k-means distortion ever increase between iterations? Can the algorithm cycle forever? What should happen when a point is equidistant from two centres?

Key: Distortion never increases (both steps are non-increasing — Moed B Q8). It cannot cycle: finitely many assignments + monotone decrease ⇒ no assignment repeats. Ties need a fixed tie-break rule (e.g. lowest index) so each changed assignment strictly lowers $J$ and progress is guaranteed.
Study tip

When a new exam question appears, first name its slot (1–8), which fixes the chapter, then ask "what is the extra input, and is it a boundary signal (→ smoothness weight) or a measurement (→ data term / seed)?" That single question answers slots 1, 6, 7 outright, and the online/efficiency and domain-transfer recipes cover the rest.
