Building matting.py, step by step

Thirteen steps, in the order you would actually type them. Each step names the module it belongs to, states its contract (what goes in, what comes out, with shapes and dtypes), gives the one formula it implements and the lecture section it comes from, shows the real code from our file, explains why it's written that way, and ends with a checkpoint you can run before moving on. Nothing here is pseudocode — every snippet is the actual content of Code/matting.py. And every algorithmic step is a course algorithm: the colour model is the joint 3-D Parzen KDE evaluated with the low-rank scheme of lecture §10.4, the distances are the geodesic $D_F, D_B$ of §10.1–10.2 with $W = \nabla P(F|c)$, and the composite is the pure-colour matting of §10.3 — not the naive blend.

The architecture, before the first line

Four functions, stacked. Each one is a pure transformation of the one below it, which is why you can build and test them bottom-up — every leaf is verifiable without ever opening a video file.

Why bottom-up and not top-down The bottom two functions take NumPy arrays and return NumPy arrays. No video, no OpenCV I/O, no disk. You can check both in a REPL in ten seconds. If you write matting() first and the output looks wrong, you have four suspects and a 40-second render loop between you and each of them. Build the leaves, prove them, then you only ever have one new suspect at a time.

The dtype discipline that prevents 80% of matting bugs

Masks are uint8 holding 0 or 1 — not 0/255, not bool. OpenCV's erode and dilate want uint8, and keeping the values at 0/1 means dilated - fg_core is a clean subtraction. If you carry 0/255 masks, that line silently produces garbage. Boolean views (band, fg_bool, rim_f…) are derived once and used for indexing. Alphas are float32 in [0,1] everywhere internally, and only become uint8 at the moment of writing.

Read the contract before writing anything

module boundary

Matting is stage 3 of 4. It does not get to choose its inputs. The project PDF (FAQ #7) fixes them, and the stage after it (tracking) depends on a property of its output. Write this down before you type import cv2.

module matting.py — turn a segmented person into a person on a new background in stabilize_ID1_ID2.avi the colours c(x) (H,W,3) uint8, per frame binary_ID1_ID2.avi the mask α_T seed (H,W,3) uint8, per frame background.jpg the new bg B(x) any size — we resize out alpha_ID1_ID2.avi opacity α(x) ×255 uint8, 3ch (FAQ #5) matted_ID1_ID2.avi composite J(x) (H,W,3) uint8 return (alpha_done_time, matted_done_time) wall-clock, for timing.json invariant where α = 0, the matted frame equals the resized background exactly └─ tracking.py detects the person as |J − B| > 30. Break this and tracking breaks.
Why the invariant matters more than it looks

That last line is the only coupling between matting and tracking, and it is invisible if you don't write it down. It's why _process_frame returns np.zeros rather than something "close to zero" when the person is absent, and why the composite must use the same resized background array the tracker will later subtract. Design the invariant in; don't discover it in stage 4.

Two constants that aren't knobs

EPS is a load-bearing guard, not a tuning parameter: density + EPS keeps a colour unseen by both models from producing $0/0$ in the Bayes ratio (it produces a neutral $0.5$ instead), and w_f + w_b + EPS stops $0/0$ in Step 9. GEO_EPS sits in between: its presence is load-bearing (without it a flat band has zero-cost paths and the distance argument collapses), but its value only matters relative to the $|\Delta P| \le 1$ colour costs — it just has to be much smaller.

Structuring elements — build $B_\rho(x)$ once, at import

matting.py:74–77
Formula this implements — the lecture's ball and band
$$ B_\rho(x) = \{y : \|y - x\| \le \rho\}, \qquad B_\rho(\Delta) = \bigcup_{x \in \Delta} B_\rho(x) $$
_ERODE_K = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (2 * RHO + 1, 2 * RHO + 1))
_SAMPLE_K = cv2.getStructuringElement(cv2.MORPH_ELLIPSE,
                                      (2 * SAMPLE_RADIUS + 1, 2 * SAMPLE_RADIUS + 1))
_RIM_K = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
The third kernel is new machinery for the lecture algorithms

_RIM_K extracts the rims — the ~2-px-thick strips of confident foreground and confident background that touch the band (Step 8). The rims stand in for the lecture's $\Omega_F$ and $\Omega_B$ twice over: they are the source sets of the geodesic distance maps $D_F = d_L(x, \Omega_F)$, $D_B = d_L(x, \Omega_B)$, and they are the candidate pools for the §10.3 window search $N(x) \cap \{\alpha = 1\}$, $N(x) \cap \{\alpha = 0\}$. Using only the rims instead of the full confident regions is exact for the distances — any path from the band into the interior must cross the rim first, so the minimum over $\Omega_F$ is the minimum over the rim.

These two lines are the lecture's set-union formula

An MORPH_ELLIPSE element of size $(2\rho{+}1) \times (2\rho{+}1)$ is a discrete disk of radius $\rho$ — that is literally $B_\rho(x)$. And morphological dilation of a set $S$ by a disk is, by definition, $\bigcup_{x \in S} B_\rho(x)$. So cv2.dilate(mask, _ERODE_K) is not "like" the lecture's band formula; it is a character-for-character implementation of it.

Odd size $2\rho{+}1$ because a structuring element needs a well-defined centre pixel. An even-sized kernel would shift the mask by half a pixel every call.

Don't build these inside the frame loop

getStructuringElement allocates and rasterises a disk. At module level it runs once. Inside _process_frame it would run 205 times for a 205-frame video, for an identical result. Constant, so hoist it — the leading underscore signals "private, precomputed."

_kde_3d — the joint density leaf, via lecture §10.4

matting.py:80–88
in lab_samples (N, 3) uint8 — Lab colours of every sample pixel of one class out density (64,64,64) float32 — density[q] = f(q | that class), Σ ≈ 1, > 0 everywhere
Formula — the joint 3-D KDE (§10.1), evaluated with the low-rank scheme (§10.4)
$$ f(c|F) \;\propto\; \sum_{x \in \Omega_F} K\big(c,\, c(x)\big), \qquad K(c,c') \propto e^{-\frac{\|c-c'\|^2}{2\sigma^2}}, \qquad c \in \mathbb{R}^3 $$

The lecture flags the direct sum as $O(|\Omega|\cdot|\Omega'|)$ — too slow — and prescribes factorising the kernel, $K(x,y) = \sum_i \phi_i(x)\,\psi_i(y)$, computing $a_i = \sum_y \psi_i(y)$ once, then $f(x) = \sum_i a_i \phi_i(x)$: linear instead of quadratic. Our instantiation of that scheme:

  • $\psi_i$ = the indicator of colour-bin $i$ → the vector $a$ is just the 3-D histogram of the samples ($O(N)$);
  • $\phi_i(c) = K(c, \text{bin}_i)$, and the 3-D Gaussian factorises exactly across the axes, $e^{-\|d\|^2/2\sigma^2} = e^{-d_L^2/2\sigma^2} e^{-d_a^2/2\sigma^2} e^{-d_b^2/2\sigma^2}$ — a rank-1 kernel per axis → evaluating $\sum_i a_i \phi_i$ is three 1-D convolutions of the histogram ($O(\text{bins})$).

3-D histogram + separable Gaussian blur = the joint KDE, computed the way §10.4 says to compute it. Total: $O(N + \text{bins})$ per class per frame.

def _kde_3d(lab_samples):
    """Joint 3-D KDE over Lab from uint8 samples (N, 3), evaluated with the
    binned low-rank scheme of lecture 10.4. Returns a KDE_BINS^3 density."""
    q = (lab_samples >> 2).astype(np.int32)                       # 256 levels → 64 bins per channel
    idx = (q[:, 0] * KDE_BINS + q[:, 1]) * KDE_BINS + q[:, 2]     # ravel (L,a,b) → one bin index
    hist = np.bincount(idx, minlength=KDE_BINS ** 3).astype(np.float32)   # aᵢ = Σ ψᵢ  (the spikes)
    density = gaussian_filter(hist.reshape(KDE_BINS, KDE_BINS, KDE_BINS), KDE_SIGMA)  # ∗ K, separable
    density /= density.sum() + EPS    # normalise — the lecture's ∝ made concrete
    return density + EPS              # never exactly 0 — Step 4 divides by (f_F + f_B)
Line by line
  • lab_samples >> 2 — integer-divide every channel by 4, mapping 256 levels onto 64 bins. This is the quantization that defines the $\psi_i$ basis. A colour step of 4 uint8 levels is below anything the KDE bell (σ = 8 levels) can resolve anyway, so nothing is lost.
  • (q[:,0] * 64 + q[:,1]) * 64 + q[:,2] — row-major raveling of the 3-D bin coordinate into one flat index, so a single bincount builds the whole joint histogram. No Python loop over samples.
  • scipy.ndimage.gaussian_filter on the $64^3$ volume — scipy applies the Gaussian separably, one axis at a time. That's not an optimisation trick bolted on: it works only because the Gaussian factorises across dimensions, which is exactly the low-rank property §10.4 asks you to exploit.
  • density /= density.sum() — the lecture writes $\propto$ and moves on because the constant cancels in the Bayes ratio. We normalise anyway: one line, and the volume becomes a real density you can sanity-check.
  • return density + EPS — a colour seen by neither class would give $0/0$ in Step 4's ratio. With the floor it gives $\text{EPS}/2\text{EPS} = 0.5$: "no evidence" maps to "coin flip", which is the honest answer.
Why joint, and not one KDE per channel

A tempting shortcut is three 1-D KDEs multiplied together (naive Bayes). It's cheaper, but it assumes the channels are independent given the class — an extra assumption the lecture never makes, and a real one: it can't tell "dark-red" apart from a class containing dark-blue and light-red. The binned joint density costs $64^3 \times 4$ bytes ≈ 1 MB and a few milliseconds per frame, so the shortcut buys nothing. This implementation is the lecture's actual estimator.

Checkpoint — run this before writing step 4 
import numpy as np
from matting import _kde_3d, KDE_BINS

s = np.array([[100, 128, 128], [104, 128, 128], [200, 60, 128]], np.uint8)

assert d.shape == (KDE_BINS,) * 3
assert abs(d.sum() - 1.0) < 1e-2            # it's a density (up to the EPS floor)
assert (d > 0).all()                          # strictly positive EVERYWHERE — the whole point
assert d[25, 32, 32] > d[32, 32, 32] > d[55, 55, 55]   # peaks at the samples, decays smoothly
assert d[25, 32, 32] > d[25, 15, 32]                    # joint: falls off along EVERY axis

The last assert is the one a per-channel model would fail: it checks the density is high only where all three coordinates match a sample, not wherever each coordinate matches some sample.

_posterior_fg — Bayes over the joint KDE

matting.py:91–98
in lab_roi (h,w,3) uint8 — the cropped frame, in CIE-Lab fg_samples (Nf,3) uint8 — colours known to be foreground bg_samples (Nb,3) uint8 — colours known to be background out p_fg (h,w) float32 — P(F | c(x)) for every pixel, in [0,1]
Formula — Bayes with uniform priors (§10.1)
$$ P(F|c) = \frac{f(c|F)\,P(F)}{f(c|F)P(F) + f(c|B)P(B)} \;\;\overset{P(F)=P(B)=\frac12}{=}\;\; \frac{f(c|F)}{f(c|F) + f(c|B)} $$

with $f(c|F)$ and $f(c|B)$ the two joint densities from Step 3 — no factorisation, no extra assumption. This is the lecture's equation verbatim.

def _posterior_fg(lab_roi, fg_samples, bg_samples):
    """P(F|c) per pixel: Bayes with uniform priors over the two KDE models."""
    f_f = _kde_3d(fg_samples)
    f_b = _kde_3d(bg_samples)
    q = lab_roi >> 2                              # same quantization as the density grid
    pf = f_f[q[..., 0], q[..., 1], q[..., 2]]   # ← fancy-index: whole image, one lookup
    pb = f_b[q[..., 0], q[..., 1], q[..., 2]]
    return pf / (pf + pb)
The one idea: evaluation is a table lookup

f_f is a $64^3$ volume. q is the image with every channel quantized to the grid. Indexing the volume with the three channel-planes replaces every pixel by its density value — the whole image, one vectorised operation. This is the payoff of the §10.4 scheme in Step 3: all the kernel sums were precomputed into the volume, so per pixel there is nothing left to compute.

Note what disappeared relative to a naive-Bayes implementation: no per-channel loop, no logs, no log-sum-exp stabilisation. Those existed to keep a product of three small densities from underflowing. With a single joint density there is no product — the ratio pf / (pf + pb) is numerically safe as-is, because Step 3's + EPS guarantees the denominator is at least $2\,\text{EPS}$.

Checkpoint — a three-pixel image with an obvious answer

That third pixel is the important one. A colour model that returns 0.5 when the evidence is symmetric is behaving correctly, and it's exactly the case the geodesic distance maps in Step 8 exist to break.

5

Crop to the ROI, and bail out if nobody's there

matting.py:152–164
def _process_frame(frame, mask, background_f):
    """Full-frame (alpha, matted) for one stabilized frame; alpha is float32
    in [0, 1], matted is float32 BGR."""
    h, w = mask.shape
    alpha = np.zeros((h, w), np.float32)     # ← default answers: "no person anywhere",
    matted = background_f.copy()             #    so the composite defaults to pure background
    box = bbox_of_mask(mask)
    if box is None:
        return alpha, matted                 # EDGE CASE: empty mask, α ≡ 0, frame = pure background
    r0, c0, bh, bw = box
    m = SAMPLE_RADIUS + RHO + 5              # pad: everything we'll dilate by, plus slack
    r0, r1 = max(0, r0 - m), min(h, r0 + bh + m)
    c0, c1 = max(0, c0 - m), min(w, c0 + bw + m)
Why crop at all

The band lives within $\rho$ pixels of the person's contour. Building a Dijkstra graph, converting colour and collecting KDE samples over a full 1920×1080 wall would be pure waste. Cropping to the person's bounding box plus a margin is the single biggest speedup in the file, and it's free — $\alpha$ outside the box is 0 and the composite outside it is the background, which is exactly what the two default allocations already put there.

The margin $m = 25 + 7 + 5 = 37$ px is not arbitrary. It must cover every dilation we're about to perform: SAMPLE_RADIUS for the sample-collection dilation in Step 7, RHO for the band dilation in Step 6, and 5 px of slack. Too small a margin and the dilations hit the crop edge, clipping the band.

A Python subtlety that looks like a bug 
r0, r1 = max(0, r0 - m), min(h, r0 + bh + m)

r0 is being reassigned and read in the same statement. This is safe: Python evaluates the entire right-hand tuple before binding anything, so both uses of r0 see the old value. Written as two statements it would be a real bug — the second line would use the new r0 and the box would be wrong.

Edge case #1 — the person is absent

bbox_of_mask returns None for an all-zero mask. We return the zero alpha immediately. Consequence downstream: the matted frame becomes the pure background image, and the tracker's detector |J − B| > 30 finds nothing — so its Kalman filter coasts on prediction alone. All of that is correct behaviour, and all of it follows from returning exactly zeros here rather than something small-but-nonzero.

Formula — the lecture's trimap (§10.1), $\alpha_T \in \{1, 0, \phi\}$

Why we get to skip the lecture's whole Stage-1 derivation

Pages 68–70 build KDE, then Bayes, then geodesic distance maps, then $V_F$ / $V_B$, then the boundary $\Delta$ — and the only thing all that machinery produces is the silhouette. We already have the silhouette: binary.avi, from the background-subtraction stage. Skipping the derivation of something you were handed isn't cutting a corner.

And the result is the same object. Eroding by $\rho$ and dilating by $\rho$ and taking the difference gives you exactly the set of pixels within $\rho$ of the mask contour, which is $B_\rho(\Delta)$ with the mask contour as $\Delta$.

Edge case #2 — dilated - fg_core on uint8

This is an unsigned subtraction. It is safe only because $\text{fg\_core} \subseteq \text{dilated}$ always (erosion shrinks, dilation grows, same kernel). Swap the operands and every background pixel becomes $0 - 1 = 255$ by wraparound, and your band is the entire image. If you ever change the two kernels to different radii, revisit this line.

Why alpha_roi starts as fg_core

It's the trimap with $\phi \mapsto 0$. If everything after this point fails or is skipped — no band, not enough samples — you fall back to a hard binary matte. Ugly, but correct-ish and never nan. Graceful degradation, chosen deliberately: the band pixels get overwritten in Step 9, they aren't accumulated into.

Checkpoint — look at your trimap. Do not skip this. 
vis = np.zeros((*mask_roi.shape, 3), np.uint8)

You want a clean amber ribbon of roughly uniform width hugging the outline. If the band swallows a limb, RHO is too large for how thin that limb is — the erosion ate it entirely. If the band is broken or ragged, the problem is upstream in binary.avi, not here.

The & near_band is the entire point of this step

A global foreground model has to describe the person's whole body — dark hair, pale skin, blue jeans, white shoes. Wide, multi-humped, useless. But restrict the samples to a 25-px neighbourhood of the band next to, say, his elbow, and the foreground is only ever "sleeve blue" while the background is only ever "wall beige." Two tight, well-separated bumps. That is why the lecture re-estimates the distributions instead of reusing the ones from Stage 1, and the tilde in $\tilde P_F$ is its shorthand for "the good local version."

lab_roi[fg_sample_px] uses a boolean mask to index a 3-channel image, which yields an (N, 3) array of just the selected pixels' colours — exactly the "bag of samples" _kde_3d wants.

Why CIE-Lab and not BGR

The kernel $K(c,c') \propto e^{-\|c-c'\|^2/2\sigma^2}$ measures colour difference with a Euclidean norm and one $\sigma$ for all directions. That's only sane if equal numeric distances look equally different to a human eye. In BGR they don't — a gap of 6 is a big change in shadow and invisible in highlight. Lab is designed to be roughly perceptually uniform, so a single KDE_SIGMA means the same thing everywhere in colour space.

Edge cases #3 and #4 — the two guards, and what they actually prevent

if band.any() fires when dilated == fg_core, which happens when the mask fills the entire cropped ROI — erode and dilate then have no border to bite on (OpenCV's erode treats the image border as foreground by default). Only reachable if the person spans the full padded window. Cheap insurance.

if fg_sample_px.any() and bg_sample_px.any() is the one that matters, and its failure mode is worse than it looks. Trace it: erosion by $\rho$ deletes fg_core entirely when the person is everywhere thinner than $2\rho = 14$ px — a small or distant subject. Now fg_samples is empty, so np.bincount([]) gives a zero histogram, which normalises to the all-EPS floor — $f(c|F) = 10^{-8}$ uniformly while $f(c|B)$ stays orders of magnitude larger wherever real background colours live. The posterior collapses to $P(F|c) \approx 0$ everywhere, so $w_F \approx 0$, so $\alpha \equiv 0$ across the whole band — and fg_core was already empty. The person vanishes from the matted video entirely. No crash, no warning, no nan.

The mirror case (bg_sample_px empty, when the dilation fills the ROI) gives $P(F|c) \approx 1$ everywhere, so $\alpha \equiv 1$ and the new background never appears at all. Both are silent-corruption bugs. The guard falls back to the hard binary matte from Step 6, which is visibly ugly — and visibly ugly is exactly what you want a failure to be.

Geodesic distances → $\tilde D_F$, $\tilde D_B$, via Dijkstra

fn _band_graph(p_fg, domain) → ids (h,w) int32 (−1 outside), graph (n,n) sparse CSR fn _geodesic_dist(ids, graph, src) → d (n,) float64 — path cost to the nearest source node domain band ∪ rim_f ∪ rim_b — the graph never leaves the neighbourhood of the boundary
Formula — the lecture's geodesic distance maps (§10.1–10.2)
$$ L(p) = \int_p \big|\langle W(p(t)),\, \dot p(t)\rangle\big|\, dl, \qquad W(x) = \nabla_x P(F|c(x)) $$
$$ d_L(x,y) = \min_{p \in [x,y]} L(p), \qquad D_F(x) = \min_{y \in \Omega_F} d_L(x, y), \qquad D_B(x) = \min_{y \in \Omega_B} d_L(x, y) $$

A path is cheap while it stays on one side of the colour boundary (flat $P$) and pays $|\Delta P|$ the moment it crosses it. So $D_F$ is small exactly for pixels that can reach the confident foreground without crossing the person's edge.

def _band_graph(p_fg, domain):
    """Sparse 8-neighbor graph over the True pixels of `domain` whose edge
    costs discretize the lecture's geodesic length: |<W, p'>| dl with
    W = grad P(F|c), i.e. |P(u) - P(v)| plus GEO_EPS per unit step."""
    h, w = domain.shape
    ids = np.full((h, w), -1, np.int32)
    n = int(domain.sum())
    ids[domain] = np.arange(n, dtype=np.int32)          # pixel → graph-node id
    us, vs, ws = [], [], []
    for dy, dx, step in ((0, 1, 1.0), (1, 0, 1.0),
                         (1, 1, 2.0 ** 0.5), (1, -1, 2.0 ** 0.5)):   # 4 offsets = all 8 neighbours, undirected
        sl_u = (slice(0, h - dy), slice(max(0, -dx), w - max(0, dx)))
        sl_v = (slice(dy, h), slice(max(0, dx), w - max(0, -dx)))
        iu, iv = ids[sl_u], ids[sl_v]
        ok = (iu >= 0) & (iv >= 0)                    # both endpoints inside the domain
        us.append(iu[ok])
        vs.append(iv[ok])
        ws.append(np.abs(p_fg[sl_u] - p_fg[sl_v])[ok] + GEO_EPS * step)   # |ΔP| + ε·dl
    graph = csr_matrix((np.concatenate(ws),
                        (np.concatenate(us), np.concatenate(vs))), shape=(n, n))
    return ids, graph


def _geodesic_dist(ids, graph, src_mask):
    """Geodesic distance d_L(x, sources) for every graph node (lecture: D_F,
    D_B), via multi-source Dijkstra."""
    return dijkstra(graph, directed=False, indices=ids[src_mask], min_only=True)

# confident pixels bordering the band: Omega_F / Omega_B for the
# distance maps and the window N(x) of the matting search
near = cv2.dilate(band_u8, _RIM_K).astype(bool)

    ids, graph = _band_graph(p_fg, domain)
    d_f = _geodesic_dist(ids, graph, rim_f)[ids[band]]   # D̃_F at every band pixel
    d_b = _geodesic_dist(ids, graph, rim_b)[ids[band]]   # D̃_B at every band pixel
How the continuous formula becomes a graph

Discretize the path integral one step at a time. Along a step from pixel $u$ to neighbour $v$, the integrand $|\langle \nabla P, \dot p\rangle|\,dl$ is the directional derivative of $P$ times the step length — which is simply $|P(v) - P(u)|$, the change in posterior across that step. Summing over the steps of a path gives $L(p)$; minimising over paths is a shortest-path problem; and shortest paths on a non-negative graph is Dijkstra. The $+\,\text{GEO\_EPS} \cdot dl$ term is the one addition: where $P$ is flat the lecture's cost is 0 for every path, so the minimum is degenerate; the tiny per-length charge breaks the tie in favour of spatially short paths (and makes the distance collapse to scaled-Euclidean exactly where colour has nothing to say — a sensible fallback, not a distortion).

min_only=True makes scipy's Dijkstra multi-source: seed all rim nodes at distance 0 and grow one wavefront, giving $\min_{y \in \Omega}$ directly instead of one run per source pixel. Two calls on the same graph — one seeded with rim_f, one with rim_b — produce both maps.

Why the graph is tiny, and why that's exact — not an approximation

The domain is only band ∪ rim_f ∪ rim_b — a ribbon a few pixels thick around the contour, some tens of thousands of nodes, not the two million pixels of the frame. Restricting to it is exact for both maps: every path from a band pixel to anywhere in the confident foreground must pass through the inner rim first, and path costs are non-negative, so the minimum over $\Omega_F$ is attained on the rim. Same argument on the background side. This is what keeps the per-frame cost at ~0.1 s instead of seconds.

The opacity formula

matting.py:196–201
Formula — the lecture's opacity map (§10.2, typo corrected)
$$ \forall x \in B_\rho(\Delta): \quad \alpha(x) = \frac{w_F(x)}{w_F(x) + w_B(x)}, \qquad w_F(x) = \tilde D_F(x)^{-r}\,\tilde P_F(x), \quad r \in (0,2] $$
    w_f = np.power(d_f, -DIST_R) * p_fg[band]           # D̃_F^(−r) · P̃_F  — verbatim
    w_b = np.power(d_b, -DIST_R) * (1.0 - p_fg[band])   # D̃_B^(−r) · P̃_B
    a_band = (w_f / (w_f + w_b + EPS)).astype(np.float32)
else:
    a_band = p_fg[band].astype(np.float32)      # no rims → no distances; colour alone decides
alpha_roi[band] = a_band                        # only the band — the rest keeps its hard 0/1
Read it as a vote

Each side casts a vote whose loudness is (how well the colour matches) × (how close it is). $\alpha$ is the foreground's share of the total vote. Because it's a share, it lands in $[0,1]$ with no clamping — the same structural trick as the Bayes formula in Step 4.

Multiplication means either factor can veto. A pixel whose colour is clearly background ($p_{fg} \approx 0$) loses even if it's touching the person. A pixel geodesically far from the confident foreground ($d_f$ large, so $d_f^{-2}$ tiny) loses even if its colour is a perfect match. Both kinds of evidence must agree.

The distances are now path costs, not pixels — roughly $\text{GEO\_EPS} \times \text{length}$ while a path stays on one side of the colour edge, plus $|\Delta P|$ if it crosses. Three cases worth being able to recite:

  • A band pixel on the person's side of the edge: reaching the FG rim is flat ($d_f \approx \text{GEO\_EPS}\cdot 3 = 0.003$), reaching the BG rim crosses the edge ($d_b \approx 0.5$). The ratio $d_f^{-2}/d_b^{-2} \approx 3\times10^4$ — geometry wins by orders of magnitude, and α snaps to 1 without any clamp.
  • A blurred pixel where the posterior is flat across the whole band: both paths are flat, so $d_f, d_b$ reduce to scaled Euclidean and nearly cancel mid-band → $\alpha \approx p_{fg}$. Geometry neutral, colour decides.
  • Same position, $p_{fg} = 0.1$ instead of $0.6$ → $\alpha \approx 0.1$. Same geometry, different colour, wildly different alpha. This is how a wisp of hair survives.
Edge case #5 — why $d^{-r}$ needs no guard here

The lecture wants $w_F \to \infty$ as $\tilde D_F \to 0$ so that α joins the trimap seamlessly at the band's edge. In the old Euclidean version $d_f$ could be exactly 0 inside the map, forcing a $d+1$ fudge that flattened the curve. Here the sources (the rims) are not band pixels, so every band pixel's distance is at least one step: $d \ge \text{GEO\_EPS} > 0$. The power is always finite, yet $d^{-2}$ still spans ~6 orders of magnitude across the band — the seamless-join behaviour the lecture intended, with no fudge and no clamp.

The opposite extreme also takes care of itself: a band pixel unreachable from a rim (an isolated speck in the mask) gets $d = \infty$ from Dijkstra, and NumPy evaluates $\infty^{-2} = 0$ — that side's vote silently drops out. No special case in the code.

Edge case #6 — + EPS in the denominator

If a band pixel is unreachable from both rims, both weights are 0 and $0/0$ = nan — a black speck in the written frame. The EPS makes it $0/\text{EPS} = 0$ instead: an unexplainable speck defaults to background. It also covers genuine float underflow when both distances are large and both posteriors extreme.

Edge case #7 — the else branch

If either rim is empty (a mask fragment with no confident interior, or one flush against the ROI edge), there are no Dijkstra sources and no distances. The fallback $\alpha = \tilde P_F$ is still a lecture formula — Bayes from §10.1 — just without the geometric term. Better than discarding the band.

_pure_composite — the lecture's matting

matting.py:130–149, 202–207
in frame_f (h,w,3) float32 BGR · a_band (n,) · band, rim_f, rim_b (h,w) bool · bg_roi (h,w,3) float32 out J (n, 3) float32 — the composited colour of every band pixel
Formula — matting with the recovered pure foreground colour (§10.3)
$$ (x_F^*, x_B^*) = \arg\min_{\substack{x_F \in N(x) \cap \{\alpha=1\} \\ x_B \in N(x) \cap \{\alpha=0\}}} \big\|\alpha(x)\,c(x_F) + (1-\alpha(x))\,c(x_B) - c(x)\big\|^2 $$
$$ J(x) = \alpha(x)\, c(x_F^*) + \big(1 - \alpha(x)\big)\, B_{\text{new}}(x) $$

The naive blend $J = \alpha c + (1-\alpha)B$ is the one the lecture says "we won't do that" about: $c(x)$ on the band already mixes the person with the old background, and the residue $J_{\text{naive}} - J_{\text{correct}} = \alpha(1-\alpha)(b_{\text{old}} - f)$ is the halo — zero at both confident ends, maximal at $\alpha = 0.5$. So §10.3 first recovers the pure foreground colour: assume some confident-FG neighbour has the same surface colour $f$ and some confident-BG neighbour has the same $b$, and pick the pair that best reconstructs the observed mixture.

def _pure_composite(frame_f, a_band, band, rim_f, rim_b, bg_roi):
    """Lecture 10.3 matting for the band pixels: find the confident pair
    (x_F*, x_B*) minimizing ||alpha*c(x_F) + (1-alpha)*c(x_B) - c(x)||^2 and
    composite with the pure foreground color c(x_F*)."""
    n = int(band.sum())
    kf, kb = min(N_CAND, int(rim_f.sum())), min(N_CAND, int(rim_b.sum()))
    a1 = a_band[:, None]
    if kf == 0 or kb == 0:
        return a1 * frame_f[band] + (1.0 - a1) * bg_roi[band]   # no candidates → direct blend
    band_yx = np.column_stack(np.nonzero(band))
    idx_f = cKDTree(np.column_stack(np.nonzero(rim_f))).query(band_yx, k=kf)[1]   # N(x) ∩ {α=1}
    idx_b = cKDTree(np.column_stack(np.nonzero(rim_b))).query(band_yx, k=kb)[1]   # N(x) ∩ {α=0}
    cand_f = frame_f[rim_f][idx_f].reshape(n, kf, 3)          # candidate FG colours per band pixel
    cand_b = frame_f[rim_b][idx_b].reshape(n, kb, 3)          # candidate BG colours per band pixel
    a = a_band[:, None, None, None]
    recon = a * cand_f[:, :, None, :] + (1.0 - a) * cand_b[:, None, :, :]   # all kf×kb mixtures
    err = ((recon - frame_f[band][:, None, None, :]) ** 2).sum(-1)          # ‖·‖² per pair
    best_f = err.reshape(n, -1).argmin(1) // kb               # the argmin's FG index, x_F*
    pure_f = cand_f[np.arange(n), best_f]                     # c(x_F*) — the recovered pure colour
    return a1 * pure_f + (1.0 - a1) * bg_roi[band]            # J = α·c(x_F*) + (1−α)·B_new

How the window $N(x)$ became a k-d tree

The lecture "opens a window around the pixel" and searches confident pixels inside it. The candidates live on the rims (Step 2), so "confident pixels near $x$" = "nearest rim pixels to $x$" — which is exactly the query a cKDTree answers, for all band pixels at once. Each band pixel gets its N_CAND = 7 nearest FG and 7 nearest BG candidates; broadcasting builds all $7 \times 7 = 49$ reconstructions per pixel in one tensor of shape (n, 7, 7, 3) (a few MB), and argmin picks the winning pair. No Python loop over pixels — the whole §10.3 search is five NumPy lines.

Note // kb: the argmin runs over the flattened $7\times7$ pair grid, and integer division recovers the row — the FG index. We never need $x_B^*$: the lecture composites with the new background $B(x)$, so the best BG candidate's only job was to help explain the observed mixture.

The search runs in BGR, deliberately

Steps 3–4 model colour in Lab because perceptual uniformity helps a density. Here the governing equation is physical, not perceptual: $c(x) = \alpha f + (1-\alpha) b$ is how light actually mixes, and it holds in the sensor's (linear-ish) BGR — not after Lab's non-linear warp. The reconstruction error and the final blend both stay in float32 BGR.

Edge case #8 — no candidates at all

If either rim is empty, there is nothing to search and _pure_composite falls back to blending the observed colour — the naive formula, accepted knowingly for that frame's band rather than dropping the band to hard 0/1. The same degenerate frames trip the Step 9 fallback, so the two degrade together.

def matting(stabilized_path, binary_path, background_image_path,
            matted_path, alpha_path):
    cap, prm = open_video(stabilized_path)          # probe geometry only...
    w, h, fps = prm['width'], prm['height'], prm['fps']
    cap.release()                                  # ...then close it; frames_of() reopens

    if background is None:
        raise IOError('Could not read background image: {}'.format(background_image_path))
    background = cv2.resize(background, (w, h), interpolation=cv2.INTER_AREA)
    background_f = background.astype(np.float32)         # convert ONCE, not per frame

    matted_writer = create_writer(matted_path, fps, w, h)
Four decisions in twelve lines
  • Probe then release. We only need (w, h, fps). The actual reading is done by the frames_of() generator, which opens its own capture. Two captures on one file is fine; leaking one is not.
  • cv2.imread returns None on failure, it does not raise. A silent None would crash 40 lines later inside cv2.resize with a useless message. Check it here, name the file in the error.
  • INTER_AREA is the correct filter for downscaling: it averages the source pixels covered by each destination pixel, so it doesn't alias. (INTER_LINEAR would sample and produce moiré on the fjord's texture.) The project allows not preserving aspect ratio, so we force the exact frame size.
  • background_f is converted to float32 once. Inside the loop it's used 205 times — as the default composite, the ROI slice bg_roi, and the $B_{\text{new}}$ of the §10.3 blend. Converting per frame would allocate a fresh 1920×1080×3 float array every iteration for no reason.

The frame loop

Four small things, each with a reason
  • zip(frames_of(a), frames_of(b)) walks two videos in lockstep, one frame of each in memory at a time. The stabilized frame supplies $c(x)$; the binary frame supplies the trimap seed. zip also stops at the shorter one, which is the behaviour you want if a codec drops a trailing frame.
  • > 127 and not == 255. binary.avi was written as 3-channel 0/255, but XVID is lossy — a "255" can come back as 251, a "0" as 4. Thresholding at the midpoint is robust to that; equality testing is not. This is the single most common way to get an empty mask and wonder why every frame is pure background.
  • cv2.merge([alpha_u8]*3) — $\alpha$ is one channel, but the writer was created with isColor=True. Replicating gives a grey video where brightness is opacity, which is what FAQ #5 asks for.
  • np.clip(..., 0, 255) before astype(uint8). NumPy's uint8 cast wraps, it doesn't saturate: 256.4 becomes 0, not 255. Float rounding around $\alpha \approx 1$ will produce 255.0000001. Clip first, always.

Notice how little is left here: the composite moved into _process_frame (Steps 6 and 10), because the §10.3 blend needs the band, the rims and the candidate search — none of which exist at this level. The loop just converts, writes, and counts.

Why the timestamp goes after release()

The project asks for the time at which each video "finished being filled with all its frames." VideoWriter buffers. Frames are still in flight when the last write() returns; release() is what flushes them and finalises the AVI container. Taking time.time() before the release would report a moment when the file on disk is incomplete.

Also: two separate releases, two separate timestamps. timing.json wants time_to_alpha and time_to_matted as distinct numbers, and main.py subtracts the pipeline start time from each.

Returning timestamps rather than durations

This function doesn't know when main.py started. Returning raw wall-clock timestamps and letting the caller subtract its own $t_0$ keeps the module ignorant of the pipeline it lives in — which is why you can unit-test it in isolation.

The one adaptation, and why it's faithful The lecture's §10.1 derives the trimap from sparse scribbles: KDE → $P(F|c)$ → geodesic $D_F/D_B$ → $V_F/V_B$ → boundary $\Delta$. In this project the background-subtraction stage already hands matting a dense $V_F/V_B$ labelling (binary.avi), so re-deriving it would be circular. The mask's contour is $\Delta$, and erosion/dilation by a disc of radius $\rho$ computes $B_\rho(\Delta) = \bigcup_{x \in \Delta} B_\rho(x)$ character-for-character. Everything the scribble machinery was for — KDE, Bayes, geodesic distances — still runs, exactly once, where the lecture uses it the second time: on the refinement stage (§10.2) inside the band.

Every edge case in the file, and the guard that handles it

Eight guards. Each one exists because something specific goes wrong without it. Know what.

Guards in matting.py
#GuardLineWhat happens without it
1 if box is None: return alpha, matted 159–160 bbox_of_mask returns None for an empty mask; unpacking it raises TypeError. With the guard: $\alpha \equiv 0$, the matted frame is the untouched background copy, and the tracker coasts on its Kalman prediction. Exactly right.
2 return density + EPS 88 A colour that neither class has ever seen looks up 0 in both densities, and the Bayes ratio is $0/0 = $ nan — black specks in the matted video. With the floor it's $\text{EPS}/2\text{EPS} = 0.5$: "no evidence" becomes "coin flip", and the distance term decides.
3 if band.any() 179 Degenerate frame where the mask fills the whole ROI, so erosion and dilation coincide and the band is empty. Everything downstream then indexes with an empty boolean mask. Falls back to the hard binary matte from alpha_roi = fg_core, with the frame pasted over the core.
4 if fg_sample_px.any() and bg_sample_px.any() 184 The important one. If the person is everywhere thinner than $2\rho = 14$ px, erosion deletes fg_core and there are no foreground samples. _kde_3d of an empty bag returns the all-EPS floor, the posterior collapses to $\approx 0$, and $\alpha \equiv 0$: the person silently vanishes from the matted video. The mirror case (no background samples) gives $\alpha \equiv 1$ and the new background never appears. No crash, no nan — the guard falls back to the hard mask, which fails visibly.
5 if rim_f.any() and rim_b.any() 191, 199–200 No rim pixels ⇒ no Dijkstra sources; indices=[] would produce nonsense distances. The else branch drops the geometric term and uses $\alpha = \tilde P_F$ — still §10.1 Bayes, just colour-only.
6 np.power(d_f, -DIST_R) with d ≥ GEO_EPS or ∞ 196–197 Not an if, a construction: band pixels are never Dijkstra sources, so $d \ge \text{GEO\_EPS} > 0$ and the power never divides by zero; unreachable pixels get $d = \infty$ and $\infty^{-2} = 0$ quietly removes that side's vote. The lecture's $\alpha \to 1$ boundary behaviour emerges from the $10^6$-fold dynamic range of $d^{-2}$, with no clamp.
7 w_f / (w_f + w_b + EPS) 198 A band pixel unreachable from both rims has $w_F = w_B = 0$, and $0/0 = $ nan. With EPS it's $0/\text{EPS} = 0$ — the orphan speck defaults to background.
8 if kf == 0 or kb == 0 (in _pure_composite) 137–138 The §10.3 pair search needs at least one candidate on each side. With none, it degrades to blending the observed colour — the naive formula, accepted knowingly for that band, on the same degenerate frames that trip guard #5.
Two more guards that aren't if statements

(binary_frame[..., 0] > 127) on line 230 guards against lossy-codec drift in binary.avi, and np.clip(..., 0, 255) on lines 233 and 235 guards against NumPy's wrapping uint8 cast, where 255.3 becomes 0 rather than 255. Both are silent-corruption bugs rather than crashes, which makes them the expensive kind.

The shape of the whole thing, in one sentence Build pure array functions you can prove correct in a REPL (_kde_3d, _posterior_fg, _band_graph, _geodesic_dist, _pure_composite); wrap them in a per-frame engine that crops to the person, morphology's a trimap, runs Dijkstra over the band, evaluates the $D^{-r}\tilde P$ formula, and recomposites with recovered pure colours (_process_frame); then wrap that in a loop that reads two videos in lockstep and writes two more (matting). Every algorithmic piece is a lecture section — §10.1 trimap and Bayes, §10.2 opacity, §10.3 matting, §10.4 fast KDE. Everything else in this document is a guard, a dtype, or a reason.
