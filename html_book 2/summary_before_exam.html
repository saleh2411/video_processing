Fast answers to the two “property” questions.
• Is $D(P,Q)=\max_{p}\min_{q}\lVert p-q\rVert$ symmetric? No. Counter-example: $P=\{0\}$, $Q=\{0,10\}$. $D(P,Q)=0$ (the single $p$ has an exact match), but $D(Q,P)=10$ (the point $10\in Q$ is far from all of $P$). It’s a directed Hausdorff-type distance.
• Does k-means terminate? Yes. Each step (assign, then recompute means) never increases the distortion $\sum\lVert x-\mu_{c(x)}\rVert^2$; there are finitely many possible assignments, and no assignment repeats before convergence ⇒ it stops in finite steps (at a local minimum).

🧰 Recurring toolbox — the moves behind everything

The whole course is a handful of tools reused. If you can name the tool a question wants, you’re half done.

Count unknowns vs. equations. Model has $k$ params, each match gives $m$ equations ⇒ need $\ge k/m$ matches. Linear→2 pairs, affine→3, homography→4. More = over-determined ⇒ Least Squares $x=(A^\top A)^{-1}A^\top b$.
Data term + prior (ML vs MAP). When data alone is ambiguous/under-determined, add a smoothness prior (Laplacian of the field). HS, super-resolution, matting all = “fit the data and look smooth/real.” Weight $\alpha$ = how much to trust the prior.
Iterate: predict → correct. Kalman/particle (predict motion, correct with measurement), iterative LK (guess $P$, linearize, update), PatchMatch (propagate, randomize). Linearize a hard non-linear problem into a sequence of easy linear ones.
Dynamic programming / Bellman. “Any sub-path of an optimal path is optimal.” Powers Dijkstra, fast sweeping, geodesic distance, hyperlapse frame selection.
Model = signal + noise + likelihood. Choose a noise model ⇒ get an estimator: Gaussian ⇒ minimize squared error ⇒ mean; Laplacian/sparse ⇒ minimize absolute error ⇒ median (robust to outliers). This is Weiss.
Low-rank / SVD. If a matrix has effective rank $p\ll\min(m,n)$, replace an $O(mn)$ job with $O((m+n)p)$. Texture state-space (Ch 5) and fast KDE (Ch 10) are the same trick.

1 · Motion Representation geometry ladder

Core idea
Motion = a matrix acting on point coordinates. Climb the ladder of models only as far as you must; each rung adds flexibility and noise sensitivity. Homogeneous coordinates (append a “1”) are the trick that lets a matrix also translate and project.
Key equations
  • Linear $2\times2$: $p'=Ap$ — 4 params, needs 2 pairs. Can never translate ($A\cdot(0,0)=(0,0)$).
  • Affine $2\times3$: $p'=Ap+t$ — 6 params, 3 pairs. Keeps parallel lines parallel (no perspective).
  • Homography $3\times3$: $p'\sim Hp$, meaningful up to scale (divide by 3rd coord) — 8 DOF, 4 pairs. Adds true perspective.
  • Projection $3\times4$: $P=K[R\,|\,t]$. Pinhole: image $=Xf/Z$ (the $1/Z$ shrinks far things). $K$=intrinsics $(f,k_u,k_v,u_0,v_0)$, $[R|t]$=extrinsics.
Exam angle
Rarely a whole question — it’s the vocabulary for everything else. Be able to say which model fits (small&far→linear, medium→affine, planar/perspective→homography) and count minimum correspondences. “Intrinsics vs extrinsics,” “up to scale,” and “why homogeneous coords” are one-line gimmes.

2 · Optical Flow the bedrock — appears every exam

Core idea
For every pixel find its motion arrow $(u,v)$ under brightness constancy (a point keeps its intensity when it moves). One pixel gives one equation for two unknowns ⇒ under-determined ⇒ you need an extra assumption (a window, or global smoothness).
Key equations
  • Brightness-constancy / flow constraint: $I_x u + I_y v + I_t = 0$ (one line in $(u,v)$-space per pixel).
  • Lucas–Kanade — assume one flow per window, solve the $2\times2$ over-determined system: $$\begin{bmatrix}\sum I_x^2 & \sum I_xI_y\\ \sum I_xI_y & \sum I_y^2\end{bmatrix}\!\begin{bmatrix}u\\v\end{bmatrix}=-\begin{bmatrix}\sum I_xI_t\\ \sum I_yI_t\end{bmatrix}$$ Solvable iff the structure tensor $A^\top A$ has rank 2.
  • Rank test: 0 = flat (untrackable), 1 = edge (aperture problem), 2 = corner (trackable).
  • Harris = the same $A^\top A$, repurposed to find corners (both eigenvalues large).
  • Horn–Schunck — global, add a smoothness prior: $$\min_{u,v}\iint (I_xu+I_yv+I_t)^2+\alpha^2\big(\lVert\nabla u\rVert^2+\lVert\nabla v\rVert^2\big)\,dx\,dy$$ $\alpha$ small→trust data (choppy); $\alpha$ large→assume smooth world. Huge sparse linear system, solved iteratively.
LK vs HS
LK = local, per-window, sparse output, tiny fast solve. HS = global, dense output, smoothness couples every pixel. Both are the same data term; HS just adds the prior. Large motion? Pyramid LK (a 32-px motion is 1 px at 1/32 scale).
Fails when
Brightness constancy breaks (specular highlights, shadows, auto-exposure); large jumps; textureless regions; motion along an edge (aperture). Basic HS blurs motion boundaries.
Exam angle — the #1 slot
“Modify Horn–Schunck to also use extra input X.” The template answer: keep the data term, and add a new penalty term that uses X to gate the smoothness. General recipe for a per-pixel side-signal $S$:
  • Add a term that only smooths flow between neighbours that agree on $S$: replace $\alpha^2\lVert\nabla u\rVert^2$ with $\sum_{\text{nbrs}} w_{pq}\lVert u_p-u_q\rVert^2$, where $w_{pq}=1$ if $S_p=S_q$ (same class / similar depth) and $\approx 0$ across a boundary. Now flow stays smooth within an object and is free to jump between objects.
  • Semantic segmentation (Moed A): $w_{pq}=1$ iff $S_1$ labels match ⇒ don’t smooth flow across a car/road boundary. Optionally forbid matches whose labels differ ($S_1(x)\ne S_2(x{+}u)$).
  • Sparse depth / LiDAR (Moed B): where depth is known, points at similar depth share motion ⇒ weight smoothness by depth similarity; can also add a data term rewarding flow consistent with the known depth (equal-depth pixels move together).
Always state: (1) the objective, (2) what term you added and why, (3) that it’s still a sparse linear system solved iteratively.

3 · Applications of Motion Estimation super-res · RANSAC · hyperlapse

Core idea
Once you know motion, redistribute pixel information across time to get something a single frame can’t give: more detail (super-resolution), fewer/smoother frames (hyperlapse), robust fitting despite bad matches (RANSAC).
Key equations
  • Super-resolution forward model: $Y_i = D\,H\,F_i\,X$ (decimate · blur · warp · HR image). ML: $\min_X\sum_i\lVert DHF_iX-Y_i\rVert^2$, solved by gradient descent $X_{n+1}=X_n-\beta\sum_i F_i^\top H^\top D^\top(DHF_iX_n-Y_i)$. MAP: add a smoothness prior so $X$ also looks like a real image. Works only because hand-shake puts each frame on a different sub-pixel grid.
  • RANSAC: pick the minimum sample (2 pts→line, 3→affine), count inliers, repeat, keep the model with most votes, refit on inliers. Iterations $K=\dfrac{\log(1-P)}{\log(1-w^n)}$ ($w$=inlier fraction, $n$=sample size).
  • Hyperlapse: pick a frame subset minimizing $C=C_m(\text{smoothness})+C_s(\text{hit target speed }\mu)+C_a(\text{even pacing})$ by dynamic programming; uniform sub-sampling fails (random phase = looks like shake). BRIEF descriptor + Hamming distance for fast matching.
Exam angle
Know RANSAC cold (minimum sample size + why, the $K$ formula) — it’s the generic robust-fitting tool that shows up inside other answers. Super-res = the clean example of ML vs MAP and “iterate instead of invert.”

4 · Kalman & Particle Filters online tracking

Core idea
Online = frames arrive one at a time. A filter fuses belief-so-far with each new measurement: predict with a motion model, then correct with data. Store only a small state, not the whole video.
Key equations
  • Bayes recursion (Moed B derivation): with the Markov assumption $p(x_t|x_{1:t-1})=p(x_t|x_{t-1})$ and conditional independence of observations $p(z_t|x_{1:t},z_{1:t-1})=p(z_t|x_t)$, $$p(x_{1:t}|z_{1:t})\ \propto\ \underbrace{p(z_t|x_t)}_{\text{measure}}\,\underbrace{p(x_t|x_{t-1})}_{\text{motion}}\,p(x_{1:t-1}|z_{1:t-1}).$$ Derive it by Bayes on $z_t$, then split the joint using the two assumptions.
  • Kalman (optimal for linear + Gaussian). Predict: $\hat x^-=\Phi\hat x,\ P^-=\Phi P\Phi^\top+Q$. Update: gain $K=P^-H^\top(HP^-H^\top+R)^{-1}$, $\hat x=\hat x^-+K(z-H\hat x^-)$, $P=(I-KH)P^-$. Gain is a trust dial: $R\to0\Rightarrow K\to1$ (trust data); $R\to\infty\Rightarrow K\to0$ (trust model). $H$ projects state→measurement (e.g. it exposes position but not velocity).
Particle filter (Condensation)
Represent any (multimodal, non-Gaussian) belief as $N$ weighted samples. Loop: Resample (draw $N$ new particles ∝ weights — the cumulative-array + uniform-$r$ roulette wheel) → Predict (push each through motion + noise) → Measure (weight ∝ $e^{-\text{SSD}}$) → Normalize. Output = weighted mean (smooth) or max-weight (sharp). Add diffusion noise every step to avoid sample impoverishment.
Exam angle
“Simulate a loaded die from rand()” (Moed A) = the resampling step. Build the CDF $c_k=p_1+\dots+p_k$; draw $r\sim U[0,1]$; return the first face $k$ with $c_k\ge r$. That’s exactly how a particle filter samples ∝ weights.
Also common: derive the Bayes recursion (state both assumptions!). Kalman vs particle: use particles for non-linear / non-Gaussian / multimodal; Kalman is far cheaper for small linear-Gaussian states.

5 · Texture Synthesis (Dynamic Texture) SVD + state-space

Core idea
A “dynamic texture” (flame, water, swaying grass) has stationary statistics — it looks similar over time without literally repeating. Model each frame as generated by a small hidden state that drifts by a linear rule + noise.
Key equations
  • State-space (ARMA): $x_{t+1}=A x_t + v(t)$ (state drift), $\ y_t = C x_t + w(t)$ (render frame).
  • Learn from a clip: stack frames into $Y$, take SVD $Y=U\Sigma V^\top$; set $C=U$ (eigen-images), states $x_t=\Sigma V_t^\top$; fit $A$ by least squares on the state sequence. Constraint $C^\top C=I$ fixes the otherwise non-unique ($TAT^{-1}$) solution.
  • Generate forever: pick a start state, push through $A$ with random $v(t)$, render with $C$, add pixel noise $w(t)$. Noise is essential — without it the state dies, explodes, or cycles.
Exam angle
“Synthesize long text from a short seed using Word2Vec” (Moed B) = dynamic texture by analogy: map words→vectors (Word2Vec = the “render” map $C$), learn the linear state transition $A$ from the seed’s vector sequence by LS, then roll forward with noise and map each generated vector back to the nearest word. State the model + noise + how you learn $A,C$.

6 · Layer Image Representation LK + K-means

Core idea
Video = stacked layers (background, actors, effects) composited by alpha. The inverse problem — recover layers from the final video — becomes tractable if you assume each layer moves by one affine motion (6 numbers), so pixels form a few “motion groups.”
Key equations
  • Alpha compositing: $I_k=I_{k-1}(1-\alpha_k)+E_k\alpha_k$ (the workhorse of every compositor). $\alpha\!=\!0$ transparent, $1$ opaque.
  • Layer recovery (EM-style loop): run LK on many random windows → each window = a point in $\mathbb{R}^6$ (its affine motion) → K-means in motion space → each cluster = one layer → re-fit motion per layer → repeat.
K-means in 4 lines
Drop $k$ centres → assign each point to nearest centre → move each centre to its members’ mean → repeat. Distortion never increases ⇒ always converges (to a possibly-local min; depends on init). Choose $k$ via MDL, or just try 2–5. This “assume one, solve the other, swap” is the same chicken-and-egg as EM.
Exam angle
“Does k-means terminate?” (Moed B) → Yes, monotone-decreasing distortion + finitely many assignments (see the map box). Also: label propagation on a graph (social network / point cloud) reuses “group by similarity + a few labelled seeds.”

7 · Video Magnification Eulerian

Core idea
Reveal invisible motion (a pulse, a swaying bridge). Lagrangian = follow each pixel (needs motion estimation). Eulerian = sit at a fixed pixel and amplify how its value changes over time — no motion estimation at all, just temporal filtering.
Key equation
Taylor: $I(x,t)\approx f(x)+\delta(t)f'(x)$. The temporal change is $B(x,t)=\delta(t)f'(x)\approx I_2-I_1$. Amplify by adding $\alpha$ copies back: $$I_1+\alpha B\ \approx\ f\big(x+(1{+}\alpha)\delta\big)$$ — the motion is magnified $\times\alpha$ without ever computing $\delta$. In practice: $B\approx I_2-I_1$, scale by $\alpha$, add to $I_1$. Band-pass the temporal signal first (e.g. 1–2 Hz for heart-rate) so you don’t amplify lighting drift and noise.
Fails when
Motion $\gtrsim 1$ px — Taylor breaks ⇒ ringing/ghosting. Fix: pyramid, amplify each spatial scale separately.
Exam angle
Know why no motion estimation is needed (the temporal difference is the change-in-value) and why sub-pixel motion is recoverable. Contrast Eulerian vs Lagrangian in one line.

8 · Background Subtraction per-pixel GMM

Core idea
A pixel’s value over time isn’t constant but isn’t random — it oscillates among a few modes (sky, leaf, passing car). Model each pixel independently as a mixture of a few Gaussians; anything matching no mode is foreground.
Algorithm (per pixel, per frame)
Keep $K\!=\!3\text{–}5$ Gaussians, each with mean $\mu_k$, width $\sigma_k$, weight $\omega_k$.
  1. Does the new value match a Gaussian within 2.5σ? If yes → nudge its $\mu,\sigma$ toward it, bump $\omega$. If no → replace the weakest Gaussian with one centred here (probably a moving object).
  2. Renormalize weights.
  3. Decide: sort by $\omega/\sigma$ (frequent and tight = strong background); the top ones whose weights sum past threshold $T$ are background, the rest foreground.
Why $\omega/\sigma$? Background is seen often (high $\omega$) and is stable (low $\sigma$); a fresh moving object has low $\omega$, high $\sigma$.
Fails when
Sudden lighting change (all modes stale → false positives), camera shake, and slow/parked objects get absorbed into background (learning rate $\alpha$ sets how fast). Plain frame-differencing fails on rustling trees — GMM learns that flicker as normal.

9 · Video Colorization & Geodesic Distance geodesic · Dijkstra

Core idea
Colour a B&W video from a few scribbles by propagating chrominance (invent U,V; keep the original luminance Y). Works because colour edges coincide with luminance edges. The engine is geodesic distance: distance that follows image content instead of straight lines.
Key equations
  • Geodesic distance: path cost = how much it crosses image edges, $d(a,b)=\inf_\Gamma\int_0^{l(\Gamma)}\sqrt{1+\gamma^2\big(\nabla I(s)\cdot\Gamma'(s)\big)^2}\,ds$. Staying inside one region is cheap; crossing a boundary is expensive. $D_k(x)$ = geodesic distance from $x$ to scribble $k$.
  • The $\gamma$ parameter (Moed A): $\gamma=0$ ⇒ the integrand is $1$ ⇒ pure Euclidean distance (ignores image, smooth round contours). $\gamma>0$ ⇒ image gradients dominate ⇒ distance hugs edges, contours wrap around objects. So the smooth/round map is $\gamma=0$; the one that follows the silhouette is $\gamma>0$.
  • Blend: $c(x)=\dfrac{\sum_k W(D_k)\,c_k}{\sum_k W(D_k)}$, weights $W(D)=1/D^{\,b}$; larger $b$ = sharper boundary.
Computing it
Bellman: a sub-path of a shortest path is shortest. Dijkstra: nodes=pixels, edge weight=|gradient|, scribbles=0, pop-smallest + relax, $O(N\log N)$. Fast sweeping (Danielsson): raster scans instead of a priority queue — GPU-friendly, ~4 sweeps. Video: gradient has a time component (x,y,t), 6 neighbours ⇒ far fewer scribbles (colour flows across frames when objects touch).
Exam angle
“Draw the path along Lena’s hat edge from A to B” (Moed B) = shortest path where edge weight rewards staying on a strong gradient (intelligent scissors / Dijkstra with cost low along edges). “Segment a 3-D point cloud / social graph from scribbles” (Moed A/B) = the same engine: build a graph, weight edges by similarity, compute geodesic distance from each labelled seed, assign each node to its nearest seed (or a $1/D$-weighted mix for “30% finance / 70% fashion”).

10 · Video Matting trimap → alpha → composite

Core idea
Extract a foreground (person, with wispy hair) and place it on a new background. Every observed pixel is a mix $I=\alpha F+(1-\alpha)B$; the hard part is the fuzzy boundary where $0<\alpha<1$.
Three stages
  1. Trimap — label each pixel foreground(1)/background(0)/unsure(φ). Built with KDE (Gaussian bump per scribble → colour likelihoods $f(c|F),f(c|B)$) → Bayes $P(F|c)=\tfrac{f(c|F)}{f(c|F)+f(c|B)}$ → geodesic distances $D_F,D_B$ → classify; pixels within band $\rho$ of the boundary = unsure.
  2. Opacity map — re-estimate colour stats locally near the boundary, assign each unsure pixel a continuous $\alpha\in[0,1]$.
  3. Matting — naive $J=\alpha c+(1-\alpha)B_{\text{new}}$ drags the old background colour onto the new one. Fix: recover the pure foreground colour by searching a window for the confident-FG/confident-BG pair $(x_F^\ast,x_B^\ast)$ that best explains the mixed pixel, composite with $c(x_F^\ast)$.
Worth knowing
Geodesic distance breaks colour ties (man in brown jacket vs brown sofa) using spatial proximity through edges. Fast KDE via low-rank kernel: $K(x,y)=\sum_{i=1}^p\phi_i(x)\psi_i(y)$ factors the double sum into $O((N+M)p)$ instead of $O(NM)$ — the same low-rank trick as texture synthesis.

11 · Re-targeting & PatchMatch bidirectional similarity

Core idea
Resize a photo to a new aspect ratio by preserving important regions and squeezing repetitive ones (sky, grass) — not squashing or cropping. A good result is complete (keeps all source content) and coherent (invents nothing).
Key equations
  • Bidirectional similarity: $D=\alpha\,D_{\text{com}}+(1-\alpha)\,D_{\text{coh}}$. Completeness = every source patch has a match in the target (don’t lose content); Coherence = every target patch has a match in the source (don’t hallucinate). Each output pixel = weighted average of matching source patches. Needs hierarchical (pyramid) initialization — starting from black lands in a bad local minimum.
  • Is $D$ symmetric? The directed $D(P,Q)=\max_p\min_q d(p,q)$ is not symmetric (counter-example in the map box). That’s exactly why re-targeting needs both completeness and coherence.
PatchMatch (the fast NN-field)
Insight: neighbouring patches share almost the same offset. Two ops per iteration:
  1. Propagation (raster order): each pixel keeps the best of its own, its left, and its above neighbour’s offset. Alternate scan direction each iteration so info flows all ways.
  2. Random search around the current best with shrinking radius (catches what propagation missed).
4–5 iterations, ~$O(N\log W)$, ~1000× faster than brute force. Powers Content-Aware Fill. Apps: inpainting, reshuffling, object removal (weight = 0 makes an object invisible to the loss). Per-pixel update is convex given the matches.
Exam angle
“Extend 1-NN → k-NN PatchMatch” (Moed B): keep a max-heap of the $k$ best offsets per patch; in propagation, offer all $k$ of the neighbour’s candidates and keep the best $k$; in random search, sample near each of the $k$ (or the best) and re-heap. Same two ops, just maintain $k$ instead of 1.
“Clone detection” (Moed A): run PatchMatch from the image to itself; a cloned region produces a large block of patches whose nearest neighbour sits far away at a consistent offset — detect coherent clusters of equal, non-trivial offset vectors.

12 · Intrinsic Images from Sequences — Weiss ICCV’01 median of derivatives

Core idea
Every photo is $I=R\cdot L$ (reflectance/“paint” × illumination/“light”). From one image this is hopelessly ill-posed. But from many frames of a fixed scene with changing light (a webcam over a day), the paint is constant and only shadows move — and one gentle statistical assumption gives a one-line recipe: take the median.
The derivation (know this cold)
  • Log turns product into sum: $i = r + l$ (lowercase = logs).
  • Assumption: derivative-filter responses of the lighting are sparse — mostly zero (a Laplacian distribution $P(x)\propto e^{-\alpha|x|}$). Lighting is smooth almost everywhere, with rare sharp shadow edges.
  • Filtered frame $o_n=i\star f_n=r_n+(l\star f_n)$: constant paint part $r_n$ + sparse lighting part. Laplacian likelihood over frames ⇒ maximizing probability = minimizing $\sum_t|o_n-r_n|$ ⇒ the minimizer is the median: $$\hat r_n=\operatorname{median}_t\{\,i(x,y,t)\star f_n\,\}.$$ (Gaussian would give the mean, which outliers/shadows drag off; the median shrugs them off.)
  • Reconstruct the paint image $\hat r$ from its filtered responses $\hat r_n$ by least squares — a fixed deconvolution $g$ that depends only on the filters (precompute once). Then lighting falls out for free: $\hat l(x,y,t)=i-\hat r$.
The crucial subtlety
Take the median of the edge (filtered) frames, not the raw pixels. A permanently-shadowed corner has a constant brightness offset → produces zero edge → cancels, so it recovers the same reflectance as a lit region. Raw temporal median would bake that permanent shadow into the paint. Only 2 filters (horizontal + vertical difference) are used. Even an 85%-sparse cast shadow: with 3 frames paint edges recover with prob ≥ 0.93; 5 frames ≥ 0.97 (binomial — a majority of frames just needs to be “clean” at each pixel).
Exam angle
“Online reflectance $R_t$ from a stream, storing ≤256 images” (Moed A): reflectance = the median over time, and the hint “values are [0,255]” screams a histogram. Keep, per pixel, a 256-bin count of the filtered values (or of intensities) — that’s $O(256)$ memory, independent of $t$. Each new frame increments bins; the running median is read off the histogram in $O(256)$. Emit $R_t$ = reconstruct from the current per-pixel medians. This streams forever within the 256-buffer budget. State: median (not mean) because lighting is sparse/outlier-like, and histogram gives an online median.

⚡ Last-minute one-liners

  • Ch 1 Motion: matrix on coordinates; homogeneous “1” enables translate/project; params set min matches (2/3/4); LS for over-determined.
  • Ch 2 Optical flow: $I_xu+I_yv+I_t=0$; LK = window + $2\times2$; rank 0/1/2 = flat/edge/corner; HS = global + $\alpha$ smoothness. To modify HS: add a weighted term using the extra signal to gate smoothness across boundaries.
  • Ch 3 Apps: super-res $Y=DHFX$ (ML/MAP, iterate); RANSAC = min-sample + vote, $K=\log(1-P)/\log(1-w^n)$; hyperlapse = cost + DP.
  • Ch 4 Tracking: predict+correct; Kalman gain = trust dial ($R\!\downarrow\!\Rightarrow$ trust data); particles for multimodal; loaded die = CDF + uniform-$r$ resampling; know the Bayes-recursion derivation + its 2 assumptions.
  • Ch 5 Texture: $x_{t+1}=Ax_t+v$, $y_t=Cx_t+w$; learn via SVD ($C=U$); noise essential; Word2Vec text = same recipe.
  • Ch 6 Layers: $I_k=I_{k-1}(1-\alpha)+E_k\alpha$; LK→$\mathbb{R}^6$→K-means; k-means terminates (monotone distortion, finite assignments).
  • Ch 7 Magnification: Eulerian, no motion estimation; $I_1+\alpha(I_2-I_1)$; band-pass first; breaks past ~1 px.
  • Ch 8 Bg subtraction: per-pixel GMM; match 2.5σ else replace weakest; sort by $\omega/\sigma$; top-to-$T$ = background.
  • Ch 9 Geodesic: distance follows edges; $\gamma=0$ Euclidean / $\gamma>0$ hugs edges; Dijkstra vs fast sweeping; scribble propagation = segmentation on any graph.
  • Ch 10 Matting: trimap (1/0/φ) → $\alpha$ map → composite with pure $F$; KDE+Bayes+geodesic; low-rank KDE for speed.
  • Ch 11 Retarget/PatchMatch: completeness + coherence; $D$ not symmetric; PatchMatch = propagation + random search; k-NN = keep a heap of $k$; clone = self-match consistent offsets.
  • Ch 12 Intrinsic: $I=RL$; log ⇒ sum; sparse lighting edges ⇒ ML = median of filtered frames (not raw pixels); reconstruct via fixed deconv; online = per-pixel histogram median.
