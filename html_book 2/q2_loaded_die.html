Rolling an unfair die with a fair coin

The friendliest 12 points on the paper — and secretly the same machine as the particle filter's resampling step. Story, a demo you can spin, then the proof.

Moed A · 19/6/2022 · Question 2 · 12 points · TRACKING

We wish to simulate rolling a loaded (unfair) six-sided (cube-shape) die, whose probabilities are $(p_1, \dots, p_6)$. We only have access to the function $rand()$ that returns a pseudo-random number $r$ sampled uniformly in the range $[0,1]$. Suggest a way to run the simulation using $rand()$.

Why is this in the TRACKING section? Because it is step 1 of Condensation, stripped of all the tracking language. "Pick a particle with probability proportional to its weight, using one uniform random number" is "roll a loaded die." Faces = particles, $p_i$ = weights. If you can answer this you can answer the resampling step, and vice versa.

1 · The story

The unfair pizza

You want a die where 6 comes up half the time and 1 almost never. All you own is a perfectly fair spinner: it lands at a completely random spot on a circle, no favourites.

So you cheat — not on the spinner, on the board.

Cut a pizza into six slices, but make the slices different sizes: face 6 gets a huge slice, face 1 gets a sliver. Now spin the fair spinner and read off whichever slice it lands in.

The spinner is still perfectly fair. But a big slice catches the pointer more often simply because it is bigger. The unfairness lives in the board, not in the randomness.

Probability of landing on a slice = the size of that slice. Make each slice's size equal to $p_i$ and you're done. That's the entire answer.

From pizza to ruler A circle is awkward in code, so unroll it into a straight line of length 1. Each face owns a strip of the line whose length is its probability. $rand()$ throws a dart uniformly at that line. Whoever owns the spot the dart hit, wins. The list of the cut positions is called the cumulative distribution, $C$. 
p  = [0.10, 0.05, 0.20, 0.05, 0.10, 0.50]

2 · Why it works — the one-line proof

This is what earns the points, not the algorithm

Build the cumulative sums $C_0 = 0$, $C_i = C_{i-1} + p_i$ for $i=1..6$, so $C_6 = \sum_i p_i = 1$. Draw $r = rand() \sim U[0,1]$ and return the smallest $j$ with $C_j > r$.

Returning face $j$ happens exactly when $r$ lands in the interval $[C_{j-1}, C_j)$ — that is what "smallest $j$ with $C_j > r$" means. So:

$$ P(\text{face } j) \;=\; P\big(C_{j-1} \le r < C_j\big) \;=\; C_j - C_{j-1} \;=\; p_j \qquad\blacksquare $$

The middle step is the only fact used: for a uniform variable on $[0,1]$, the probability of landing in a sub-interval is that interval's length. That is the definition of uniform, and it is why the method needs $r$ to be uniform on exactly $[0,1]$ — the ruler has total length $\sum_i p_i = 1$, so it matches the range of $rand()$ perfectly.

The technique has a name worth writing down: inverse-CDF sampling (inverse transform sampling). $C$ is the CDF of the discrete distribution, and you are evaluating $C^{-1}(r)$.

If the $p_i$ don't sum to 1 Normalise first: $p_i \leftarrow p_i / \sum_k p_k$. Otherwise the ruler is shorter or longer than the range of $rand()$ — too short and some darts land past the end (undefined); too long and the last faces can never be reached. In the particle filter this is exactly the "normalise the weights so $\sum_n \Pi^{(n)} = 1$" line.

3 · Writing it as code

C[0] = 0
for i = 1..6:  C[i] = C[i-1] + p[i]        # cumulative sums, C[6] = 1

roll():
    r = rand()                              # uniform in [0,1]
    for j = 1..6:                           # smallest j with C[j] > r
        if C[j] > r: return j

The loop is $O(n)$ per roll, with $n=6$ — irrelevant here. But say the improvement anyway, because it shows you know why $C$ is built the way it is:

$C$ is sorted (probabilities are non-negative, so the cumulative sums never decrease). A sorted array means you can find the right bin by binary search in $O(\log n)$ instead of scanning. For a die that's nothing; for a particle filter with $N=200$ particles resampled $N$ times per frame, it turns $O(N^2)$ into $O(N\log N)$.

Bonus answers, if you want to show off (one line each)

• Fair die as a sanity check: with all $p_i = 1/6$ the method reduces to $j = \lfloor 6r \rfloor + 1$ — the familiar formula, which is just the equal-slices special case.

• Alias method (Walker): $O(1)$ per roll after $O(n)$ setup, using one uniform draw and a table of "each bin holds at most two faces". Better when you roll the same die millions of times.

• Systematic sampling: if you need $N$ draws at once (as resampling does), draw a single $r_0 \sim U[0, 1/N]$ and use the evenly spaced darts $r_i = r_0 + i/N$. Same expected counts, lower variance than $N$ independent draws.

5 · The answer, as you would write it in the box

Half a page is plenty — but include the proof

Method (inverse-CDF sampling). Precompute the cumulative sums $C_0 = 0$, $C_i = C_{i-1} + p_i$ for $i = 1,\dots,6$; note $C_6 = \sum_i p_i = 1$ (normalise the $p_i$ first if they do not already sum to 1). To simulate one roll: draw $r = rand() \sim U[0,1]$ and return the smallest index $j$ such that $C_j > r$, i.e. the $j$ with $C_{j-1} \le r < C_j$.

Correctness. Face $j$ is returned precisely when $r$ falls in $[C_{j-1}, C_j)$. Since $r$ is uniform on $[0,1]$, the probability of landing in an interval equals that interval's length, so $P(\text{face } j) = C_j - C_{j-1} = p_j$, as required.

Cost. $O(n)$ setup once; $O(n)$ per roll by scanning, or $O(\log n)$ by binary search since $C$ is non-decreasing (the $p_i$ are non-negative). With all $p_i = 1/6$ this reduces to $j = \lfloor 6r\rfloor + 1$. For very many rolls, the alias method gives $O(1)$ per roll.

Connection. This is exactly the select stage of the Condensation / particle-filter algorithm, where the faces are particles and the $p_i$ are the normalised particle weights $\Pi^{(n)}$.

6 · Exam drill

Q. Why must $r$ be uniform on $[0,1]$ specifically?

Because the proof uses "probability of landing in an interval = length of the interval", which is the defining property of the uniform distribution, and because the ruler's total length is $\sum_i p_i = 1$. Any other range would either leave part of the ruler unreachable or send darts past its end.

Q. Why is $C$ guaranteed to be non-decreasing, and why do you care?

Each step adds $p_i \ge 0$, so $C$ never decreases. That makes "the smallest $j$ with $C_j > r$" well-defined and unique, and it means $C$ is a sorted array — so the search can be done by binary search in $O(\log n)$ rather than a linear scan.

Q. What if some $p_i = 0$?

That face owns an empty interval ($C_{j-1} = C_j$), so no $r$ can ever fall strictly inside it, and it is never returned — which is exactly correct. The strict inequality in "smallest $j$ with $C_j > r$" is what guarantees a zero-width bin is skipped.

Q. How does this generalise to a continuous distribution?

Identically: build the CDF $F$, draw $r \sim U[0,1]$, and return $F^{-1}(r)$. The discrete case here is just $F$ being a step function, and "smallest $j$ with $C_j > r$" is how you invert a step function. This is why the technique is called inverse transform sampling.

Q. Someone hands you $N$ rolls to generate at once. Anything better than $N$ independent draws?

Systematic sampling: draw one $r_0 \sim U[0,1/N]$ and use $r_i = r_0 + i/N$ for $i = 0..N-1$. The expected count for each face is unchanged ($N p_j$) but the variance is much lower, because the darts are spread evenly instead of clumping by chance. Standard practice in particle filters for exactly this reason.

Q. Where does this exact construction appear in the tracking chapter?

Condensation, step 1 (select): "generate $r$ at random, $r \in [0,1]$; find the smallest $j$ such that $C_{t-1}^{(j)} > r$; set $S_t'^{(n)} = S_{t-1}^{(j)}$." Faces become particles and $p_i$ becomes the normalised weight $\Pi^{(n)}$. Repeating the draw $N$ times builds the resampled particle set.
