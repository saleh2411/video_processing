Companion page to Chapters 9 & 6 · Exam 8/7/2020, question 7 · 13 points

Drop $K$ pebbles in a pond, let the ripples fight

Superpixels are k-means, with one substitution: replace “distance” by geodesic distance, and the whole thing becomes a multi-source Dijkstra that cannot leak across an edge. Two ingredients you already own — nothing new is required.

Exam 8/7/2020 · Question 7 · 13 points · SEGMENTATION

Superpixels is a mid-level image representation that breaks the image into small and homogenous regions called superpixels. An image is usually represented by around 1000 or 2000 superpixels, as this reduces the computational burden of subsequent tasks. See Figure 5 for an example. Write a pseudo-code of an algorithm that uses geodesic distances to calculate superpixels of an image. Your algorithm should take as input the image and the number of requested superpixels.

The 30-second version — read this first It is k-means with a geodesic metric, i.e. a Lloyd iteration:
1. $S=\sqrt{N/K}$; place $K$ seeds on a regular $S$-grid, nudged to the lowest-gradient pixel in a $3\times3$ window.
2. Assign: run multi-source Dijkstra from all $K$ seeds at once on the pixel graph with edge weights $w(p,q)=\sqrt{\|p-q\|^2+\gamma^2\|I(q)-I(p)\|^2}$. Each pixel takes the label of the seed that reaches it first — a geodesic Voronoi tessellation.
3. Update: move each seed to its region's centroid (snapped back onto the region).
4. Repeat 2–3 until the seeds stop moving; then enforce connectivity and absorb tiny fragments.

Cost: $O(N\log N)$ per iteration, $\approx 10$ iterations.

1 · The story (no math at all)

Pebbles in a pond with walls in it

Picture the picture as a shallow pond. Now build little walls in the pond wherever the picture has an edge — where the bear stops and the water starts, there is a wall. Inside the bear, flat ground. Inside the water, flat ground.

Now drop $K$ pebbles into the pond, spread out evenly, and let each pebble send out a ripple. The ripples spread at the same speed — except they have to climb over walls, which slows them down a lot.

Every drop of water in the pond belongs to whichever ripple got there first.

What happens? A ripple started inside the bear races freely around the bear, but it stalls at the bear's outline. A ripple started in the water fills water. So the little territories you end up with automatically stop at the object boundaries — nobody told them where the bear is; the walls did it.

One more round: after the first fight, each pebble was probably not sitting in the middle of the territory it won. So pick it up, put it in the middle, and run the ripples again. A few rounds and it settles down. That settling-down loop is exactly k-means; the walls are the only new part.

Why bother? Because now you have ~1000 tiles instead of a million pixels, and every tile is one colour and one material. Whatever you wanted to do next — tracking, matting, segmentation, colorization — you now do on 1000 things instead of a million, and none of your tiles straddles a boundary.

Where the “walls” come from They are the same geodesic metric as the colorization/matting chapter: $d(a,b)=\inf_\Gamma\int_0^{l(\Gamma)}\sqrt{1+\gamma^2(\nabla I\cdot\Gamma')^2}\,ds$. The “1” charges for walking; the $\gamma^2(\nabla I\cdot\Gamma')^2$ charges for crossing image structure. Discretise a single pixel step and the integral becomes $\sqrt{\|p-q\|^2+\gamma^2\|I(q)-I(p)\|^2}$ — one wall per edge. See Moed A Q6 for that integrand read symbol by symbol.

2 · The pseudo-code

SUPERPIXELS_GEODESIC(I, K)                       # I : H×W×3 image,  K : requested count
────────────────────────────────────────────────────────────────────────
 1  N ← H·W                                      # number of pixels
 2  S ← round( sqrt(N / K) )                     # nominal superpixel side
 3  γ ← edge sensitivity      (e.g. 10)          # 0 ⇒ Euclidean ⇒ plain SLIC-like grid
 4  I ← smooth(I, σ≈1)  ;  convert to CIELAB     # noise ⇒ spurious walls

    # ---------- 1. seeds ------------------------------------------------
 5  seeds ← { (x,y) : x = S/2, 3S/2, … ,  y = S/2, 3S/2, … }        # regular grid, |seeds| ≈ K
 6  for each s in seeds:
 7      s ← argmin over the 3×3 window around s of ‖∇I‖             # do not start ON an edge
    # (a seed sitting on a boundary would immediately split two objects)

    # ---------- 2. Lloyd iterations -------------------------------------
 8  repeat until  Σ‖s_k − s_k^prev‖ < ε   or  T iterations (T ≈ 10):

        # ---- 2a. ASSIGN : multi-source Dijkstra = geodesic Voronoi -----
 9      D[p] ← ∞ ,  L[p] ← −1        for all pixels p
10      Q ← empty min-priority-queue
11      for k = 1 … K:
12          D[s_k] ← 0 ;  L[s_k] ← k ;  push(Q, (0, s_k))
13      while Q not empty:
14          (d,u) ← pop-min(Q)
15          if d > D[u]: continue                      # stale entry
16          for each q in Neighbours8(u):
17              w ← sqrt( ‖q−u‖²  +  γ²·‖I(q) − I(u)‖² )      # the geodesic step cost
18              if D[u] + w < D[q]:
19                  D[q] ← D[u] + w ;  L[q] ← L[u] ;  push(Q, (D[q], q))
        #  optional speed-up: only relax q if ‖q − s_{L[u]}‖∞ < 2S  (SLIC-style local search)

        # ---- 2b. UPDATE : move each seed to the middle of its region ---
20      for k = 1 … K:
21          R_k ← { p : L[p] = k }
22          c_k ← mean position of R_k                  # spatial centroid
23          s_k ← argmin_{p ∈ R_k} ‖p − c_k‖            # snap back inside the region
        #  (exact version: s_k ← argmin_{p∈R_k} Σ_{q∈R_k} d_geo(p,q) — the geodesic medoid)

    # ---------- 3. post-process ------------------------------------------
24  for each connected component C of each label:
25      if C is not the component containing s_k  or  |C| < S²/4:
26          relabel C to the adjacent label with the smallest mean colour difference
27  return L                                      # label map: ≈ K connected superpixels
────────────────────────────────────────────────────────────────────────
COST : step 2a is Dijkstra over N nodes with 8 edges each → O(N log N)
       (O(N) with a bucket queue / fast marching);  × T iterations.
The five lines that earn the marks Line 2 — $S=\sqrt{N/K}$ is how the requested number becomes a size. Line 7 — never start a seed on an edge. Line 17 — the geodesic weight; this is the whole difference from SLIC. Lines 11–12 — multi-source initialisation: one Dijkstra for all $K$ seeds, not $K$ Dijkstras. Lines 24–27 — connectivity is not guaranteed by the assignment step and must be fixed afterwards.

3 · Why every line is what it is

It is literally k-means

Line up the two algorithms and the correspondence is exact:

k-means (Ch. 6)Geodesic superpixels
$k$ cluster centres$K$ seeds, initialised on an $S$-grid
assign each point to the nearest centreassign each pixel to the geodesically nearest seed (one multi-source Dijkstra does all $K$ at once)
move each centre to the mean of its clustermove each seed to the centroid of its region, snapped back inside it
repeat; cost decreases monotonically ⇒ terminatessame argument (see B8) — but only for a fixed metric, and the metric here is fixed, so it terminates
distance = $\|x-\mu\|^2$ in feature spacedistance = the geodesic $d(p,s_k)$ — path-based, so it respects walls

Why multi-source Dijkstra rather than $K$ separate runs

You only need, for every pixel, the distance to the nearest seed and which seed that is — the point-to-set distance, not $K$ separate maps. Seeding the priority queue with all $K$ sources at distance 0 computes exactly that in one $O(N\log N)$ sweep. Running $K$ Dijkstras would cost $O(KN\log N)$ and then you would still have to take a minimum. This is the same trick as the multi-scribble distance map in colorization.

Why the search can be restricted to a $2S\times2S$ window

A pixel more than a couple of superpixel-widths from a seed will never be won by it, so relaxing those edges is wasted work. Restricting each seed's expansion to a $2S\times2S$ neighbourhood makes the assignment step $O(N)$ instead of $O(N\log N)$ — each pixel is then examined by a constant number of seeds. This is exactly SLIC's optimisation, and it is what makes 1000+ superpixels real-time.

Why connectivity must be repaired afterwards

Dijkstra's label field is almost connected but not guaranteed to be: when a seed moves in the update step, a small pocket of pixels can end up labelled $k$ while being cut off from $s_k$ by a cheaper route from another seed, and thin structures can pinch off orphan fragments. A single connected-component pass that reassigns any component not containing its own seed (and any component below $S^2/4$ pixels) to the most similar neighbouring label fixes it, and also guarantees the promised “around 1000” count is not silently inflated.

Why smooth first, and why CIELAB

Every noise spike is a wall. A mild Gaussian ($\sigma\approx1$) removes the fake walls without moving the real ones. CIELAB is used because Euclidean distance in that space is roughly perceptually uniform, so $\|I(q)-I(p)\|$ means “how different do these look” rather than “how different are these voltages”, which is what makes one global $\gamma$ work across the whole image.

4 · The answer, as you would write it in the box

Full-marks version — one page

Idea. Superpixels = k-means on the pixel grid with the geodesic metric instead of the Euclidean one. The assignment step of k-means becomes a multi-source Dijkstra from the $K$ seeds, which produces a geodesic Voronoi tessellation; because crossing an image edge is expensive, the tessellation boundaries snap to object boundaries.

Metric. On the 8-connected pixel graph, weight the edge $p\!\to\!q$ by the discretised geodesic integrand

$$ w(p,q)=\sqrt{\;\|q-p\|^2+\gamma^2\,\|I(q)-I(p)\|^2\;} $$

($\gamma=0$ gives Euclidean/compact superpixels; larger $\gamma$ gives stronger boundary adherence). Work in CIELAB and pre-smooth with $\sigma\approx1$ so that noise does not create false edges.

Pseudo-code.

GEODESIC_SUPERPIXELS(I, K):
  N ← H·W ;  S ← round(sqrt(N/K))                    # nominal side length
  I ← Lab(gaussian(I, σ=1))
  seeds ← regular grid with spacing S                # |seeds| ≈ K
  for each seed s:  s ← argmin ‖∇I‖ in the 3×3 window around s
  repeat T times (or until the seeds stop moving):
      # --- assignment: multi-source Dijkstra ---
      D[·] ← ∞ ; L[·] ← −1 ; Q ← ∅
      for k = 1..K:  D[s_k] ← 0 ; L[s_k] ← k ; push(Q,(0,s_k))
      while Q ≠ ∅:
          (d,u) ← pop_min(Q) ;  if d > D[u]: continue
          for q ∈ N8(u):
              w ← sqrt(‖q−u‖² + γ²‖I(q)−I(u)‖²)
              if D[u]+w < D[q]:  D[q] ← D[u]+w ; L[q] ← L[u] ; push(Q,(D[q],q))
      # --- update: Lloyd step ---
      for k = 1..K:  c_k ← centroid{p : L[p]=k} ;  s_k ← nearest pixel to c_k with L = k
  enforce connectivity: relabel every component not containing its seed, and any
      component smaller than S²/4, to the neighbouring label of closest mean colour
  return L

Complexity. Each assignment is one Dijkstra over $N$ nodes of degree 8, i.e. $O(N\log N)$ (or $O(N)$ with a bucket queue / fast marching), times $T\approx10$ iterations. Restricting each seed's expansion to a $2S\times2S$ window makes it $O(N)$ per iteration, since then each pixel is only considered by $O(1)$ seeds — this is what allows $K=1000$–$2000$ at video rates.

Remarks. (i) $K$ enters only through $S=\sqrt{N/K}$; the output count is approximately, not exactly, $K$, which is why the merge step matters. (ii) Termination follows from the k-means argument: the assignment step and the centroid step each do not increase the objective, and the number of labelings is finite. (iii) $\gamma$ trades compactness against boundary adherence; $\gamma=0$ degenerates to a regular grid (SLIC without the colour term), $\gamma\to\infty$ gives ragged superpixels that follow texture and noise. (iv) Seeds must not be initialised on an edge, otherwise a single superpixel straddles two objects from the start.

5 · Exam drill

Q. Why $S=\sqrt{N/K}$?

If $K$ superpixels tile $N$ pixels evenly, each owns $N/K$ pixels. A roughly square region of area $N/K$ has side $\sqrt{N/K}$. So $S$ is the natural grid spacing for the seeds, the natural search radius ($2S$), and the natural threshold for "this fragment is too small" ($S^2/4$). Every scale in the algorithm is derived from this one number, which is how the user-facing parameter $K$ propagates through.

Q. Why Dijkstra and not a plain BFS or a distance transform?

Because the edge weights are not equal. BFS computes shortest paths only when every edge costs the same, and a distance transform assumes the Euclidean metric on a uniform grid. Here the cost of a step depends on the local image gradient, so you need a genuine weighted shortest-path algorithm. Dijkstra is correct because all the weights are non-negative (they are square roots of sums of squares, hence $\ge\|q-p\|>0$). The continuous-domain alternative with the same output is fast marching / fast sweeping (Ch. 9).

Q. Does the algorithm terminate? Does it find the global optimum?

Terminates: it is Lloyd's algorithm with a fixed metric. The assignment step gives each pixel its cheapest seed (cannot increase the objective $\sum_p d(p,s_{L[p]})$), the update step moves each seed to a better representative of its own region (cannot increase it either), and there are finitely many labelings, so no labeling can repeat — see B8 for the full argument. Global optimum: no. Like k-means it is initialisation-dependent; the regular grid initialisation is what makes the result reproducible and roughly uniform in practice.

Q. What does $\gamma\to\infty$ do, and why is that bad?

The arclength term becomes negligible, so distance measures only accumulated colour variation. Ripples then flow freely through any flat region no matter how far, and superpixels become enormous, thin and ragged — they follow every texture ripple, not just object boundaries, and they lose the compactness that made them useful as a regular mid-level representation. It is also unstable in noise, since noise creates gradients. Keeping the “1” in $\sqrt{1+\gamma^2(\cdot)^2}$ is what guarantees a floor on the cost per step and hence bounded superpixel size.

Q. How is this different from SLIC?

SLIC measures a direct 5-D distance between a pixel and a seed, $D=\sqrt{d_{lab}^2+(m/S)^2d_{xy}^2}$ — it compares the pixel with the seed's colour, ignoring what lies between them. The geodesic version measures the cost of the cheapest path, so a pixel that happens to have the same colour as a seed on the other side of a strong edge is still far away. That makes geodesic superpixels much better at not leaking through thin barriers, at the cost of a shortest-path computation instead of a local comparison. Setting $\gamma=0$ collapses the geodesic version to a purely spatial grid.

Q. Why do superpixels reduce the computational burden of later tasks, concretely?

They turn a pixel grid into a graph with $\sim10^3$ nodes instead of $\sim10^6$. A graph-cut, a CRF, a label-propagation or a k-NN search then runs on that graph, typically a $10^3$-fold reduction in nodes and a similar reduction in edges. Just as important: each node carries an aggregated feature (mean colour, texture histogram, size, shape), which is far more discriminative and far less noisy than a single pixel — so you get both speed and better features. The requirement is that superpixels never straddle a true boundary, since any such error is unrecoverable downstream; that requirement is exactly what the geodesic metric buys.
