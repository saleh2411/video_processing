From profile to model

Collapse time — look at the histogram

Forget the order of frames. The histogram of the orange pixel's 205 values shows the clusters the chapter talks about — and they are Gaussian-shaped, because of sensor noise.

background mode: μ≈113, popular and tight → ω/σ large person mode: μ≈32, rare and wide → ω/σ small
Real histogram (bars) + the two fitted Gaussians. Weights: background ω≈0.67, person ω≈0.33.
🔔

Why Gaussians and not boxes: sensor + lighting noise spread each "true" colour into a bell curve around it. σ captures that spread; the 2.5σ match test later is exactly "is this value inside the bell?"

Colour space

Why the code works in CIE-Lab, not BGR

Lab separates what BGR mixes: L = illumination only, a/b = pure chroma (green-red / blue-yellow). Shadows, reflections and exposure wobble live in L; the person's clothes and skin differ in a/b. So the code makes brightness almost not count:

d² = 0.25·ΔL² + Δa² + Δb² The match distance. A pixel that only got darker (shadow) moves almost nowhere; a pixel whose COLOUR changed (person arrived) moves far. Conversion: cv2.cvtColor(frame, cv2.COLOR_BGR2Lab) - done once per frame at read time, everything downstream lives in Lab.
The experiment that decided it - frame 52, where the person walks past a glossy poster. His body measurably darkens the poster corner (~10-20% for ~10 frames). In BGR that darkening looks like "colour changed" → foreground blob glued to his head. In Lab it is almost pure ΔL → ignored. Our Lab result (3rd) is cleaner than the reference (4th).
🌕

Shadow veto becomes exact

Instead of guessing "uniform darkening" from BGR ratios, the rule is literal physics: L attenuated into [0.50, 0.96] AND |Δa|, |Δb| < 8 → cast shadow → background. Same rule OpenCV's MOG2 uses internally.

👕

Person is chroma-safe

Skin and clothes differ from walls/doors in a/b by tens of units - the full-weight channels. Down-weighting L costs the person nothing; it only forgives illumination events. Measured: person mask unchanged, poster artifact gone.

The math

The per-pixel mixture model

Each pixel keeps K = 3–5 Gaussians. Each Gaussian k stores three numbers: mean μk, width σk, weight ωk (how often it was seen; weights sum to 1).

fx(x | Φ) = Σk=1..K  ωk · 𝒩(x ; μk, σk) Covariance simplified to σI (channels independent) — the course text makes the same assumption. Classification of a new value x: MAP — pick k̂ = argmax ωk·𝒩(x; μk, σk); in the online algorithm this collapses to the cheaper match test |x − μk| < 2.5σk.
⚖️

ω — the prior

"How much of history did this mode explain?" The door mode of our orange pixel: ω≈0.67. The person mode: ω≈0.33.

📏

σ — the stability

Static surfaces → small σ (green pixel: σ≈2). Moving/new things → large σ. Sorting key uses both: ω/σ.

🗂️

Per-pixel state

K Gaussians × 3 numbers. For 1920×1080 and K=4: three float32 arrays of shape [4, 1080, 1920] — about 100 MB. Fits easily.

The decision

Which Gaussians are background? Sort by ω/σ

Background modes are popular (high ω) AND stable (low σ). Sort descending by ω/σ, take modes from the top until their cumulative weight passes T. Try it on the orange pixel's real fitted modes:

B = argminb ( Σk=1..b ωk > T ) after sorting by ωk/σk descending. The chapter suggests T ≈ 0.7–0.9 for multimodal scenes (leaves + sky). Our final code uses T = 0.3: the background here is unimodal, and testing showed higher T admits the person's own "ghost" mode where he lingers — play with the slider to see exactly that failure.
Teal = classified background, red = foreground. At T ≤ 0.67 only the door mode is background (correct). Push T past 0.67 and the person mode gets absorbed too — the classic "T too high" failure.
The algorithm

Online update — per frame, per pixel

Full EM over all frames is expensive; the chapter's streaming recipe keeps the model fresh with O(K) work per pixel per frame.

1

Match test  ·  |x − μk| < 2.5 σk

Find the first Gaussian the new value falls into. 2.5σ ≈ 99% of the bell — tight enough to catch new objects, loose enough to absorb sensor noise.

2

Matched → nudge that Gaussian

ωk ← (1−α)ωk + α  (winner grows, losers shrink)  ·  μk ← (1−ρ)μk + ρx  ·  σk² ← (1−ρ)σk² + ρ(x−μk)². With α ≈ 0.01 a new pattern needs ~100 frames to become background.

3

No match → replace the weakest Gaussian

New Gaussian centred at x, large σ, small ω: "tentative new thing, probably an object." It only earns background status if it keeps re-appearing for ~1/α frames.

4

Renormalize, then classify

Weights re-sum to 1. The pixel is foreground if its matched Gaussian is not in the background set B (or if nothing matched at all).

The recipe → the code

The 4 theory steps — and the exact code for each

The algorithm in four steps: ① per-pixel histogram over all frames → ② describe it with Gaussians (μ, σ, ω) → ③ sort the Gaussians → ④ threshold into background/foreground. All four ARE in the code — but three of them wear a disguise. Step by step:

①

"Find the histogram of each pixel among all frames"

Disguise: the histogram is never built. 500,000 pixels × 256 bins × 3 channels won't fit nicely, and we don't need the whole histogram — only its clusters. The code reads the histogram's properties directly from the raw samples instead:

# train_gmm() - the whole video as one array: axis 0 = time = "the samples"
stack = np.stack(small_frames)              # [N,H,W,3]  N=205 samples per pixel
med = np.median(stack, axis=0)              # the LOCATION of the histogram's tallest peak
mad = np.median(np.abs(stack - med[None]), axis=0).mean(axis=2)
                                            # the WIDTH of that peak (MAD ~ robust sigma)

Median over time = the most typical colour = exactly where the biggest histogram bump sits (the person can't move it — he's a minority of any pixel's samples). MAD = how wide that bump is. That's the histogram's main cluster measured without ever binning. The REST of the histogram (smaller clusters) is discovered by step ②'s loop, one sample at a time.

②

"Describe the histogram with multiple Gaussians — find each μ, σ, ω"

Disguise: the fitting is incremental. Instead of fitting curves to a finished histogram, the training loop feeds the samples one frame at a time; each sample nudges the Gaussian it belongs to. After 204 frames the three arrays mu, sigma, weight ARE the fitted mixture:

# train_gmm() main loop - each frame = one more histogram sample per pixel
for frame in small_frames[1:]:
    dist2 = ...                             # distance of the sample to every Gaussian
    match = dist2 < (2.5 * sigma)**2 * 2.25 # which cluster does this sample fall into?

    # sample falls into an existing cluster -> that cluster absorbs it:
    weight = (1-ALPHA)*weight + ALPHA*upd   # omega = FRACTION OF SAMPLES explained so far
    mu   = (1-rho_u)*mu + rho_u*frame[None] # mean drifts toward the samples it collected
    sig2 = np.where(upd, (1-rho)*sig2 + rho*dist2/3, sig2)
                                            # width grows/shrinks to the samples' spread

    # sample falls into NO cluster -> a new histogram bump was just discovered:
    mu    = np.where(repl[...,None], frame[None], mu)   # new Gaussian centred on it
    sigma = np.where(repl, SIGMA_INIT, sigma)           # wide - one sample, low confidence
    weight = np.where(repl, W_NEW, weight)              # tiny omega - barely any mass yet

Read ω as "how much histogram mass this Gaussian owns": the wall cluster collects ~140 of 205 samples → ω ≈ 0.7; the person passing collects ~60 → ω ≈ 0.3. Same numbers a histogram would give — accumulated instead of binned. (The chapter's justification: this is the real-time approximation of full EM clustering.)

③

"Sort the Gaussians of each pixel by their weights"

Disguise: the sort key is ω/σ, not ω alone. Popular AND tight beats popular-but-smeared — a background surface is both frequent and stable. One line, sorting all 500,000 pixels' Gaussians at once:

# background_set()
order = np.argsort(-(weight / sigma), axis=0)   # axis 0 = the K Gaussians, per pixel
w_sorted = np.take_along_axis(weight, order, axis=0)  # weights re-arranged best-first

argsort along axis 0 gives each pixel its private ranking of its own 4 Gaussians — the vectorized version of "for every pixel: sort".

④

"Using the threshold, sort background/foreground"

Disguise: this is TWO decisions, not one. First — done once — the threshold labels each GAUSSIAN background or foreground (walk down the ranking until the collected weight passes T):

# background_set(), continued - label the GAUSSIANS (once, after training)
cum = np.cumsum(w_sorted, axis=0)               # running weight down the ranking
in_bg_sorted = (cum - w_sorted) < T_BG          # in the set while total before me < T
np.put_along_axis(is_bg, order, in_bg_sorted, axis=0)  # un-sort back to k order

Second — done per frame — each PIXEL VALUE is tested: does it fall inside (2.5σ of) one of the Gaussians that step one declared background?

# classify_frame() - label the PIXELS (every frame)
match = dist2 < (2.5 * sigma)**2 * 2.25         # which Gaussians does this value fall in?
background = (match & is_bg).any(axis=0)        # inside a BACKGROUND one -> background
mask = (~background).astype(np.uint8)           # everything else -> person

The person's colour matches no background Gaussian (or nothing at all) → foreground. Shadow veto and mask cleanup then polish this raw decision.

🗺️

Bottom line: your 4 steps map to: ① median/MAD init + the frame loop's samples · ② the update equations in train_gmm() · ③ the argsort line in background_set() · ④ cumsum < T (labels Gaussians) + the match test in classify_frame() (labels pixels). Inside the code

How the code actually implements this

The chapter describes one pixel. The code runs the SAME equations for all ~500,000 pixels at once, using numpy array broadcasting. No loop ever visits a pixel — the only Python loop is over frames.

1 · The state: three stacked arrays

"Each pixel keeps K Gaussians" becomes three arrays whose FIRST axis is the Gaussian index k. Pixel (y, x) owns one vertical column through each stack:

"mu[2, y, x] = the mean colour of Gaussian #2 of pixel (y,x)". An operation on the whole array touches every Gaussian of every pixel simultaneously.

2 · The match test — one line, all pixels, all K

# frame:      [H, W, 3]  the new image, already converted to Lab
# frame[None]:[1, H, W, 3]  extra axis so numpy can broadcast against all K
# CH_W = [0.25, 1, 1]   channel weights: L barely counts, chroma fully
diff  = frame[None] - mu                            # [K,H,W,3] x - mu_k, every k at once
dist2 = np.einsum('khwc,khwc,c->khw', diff, diff, CH_W) # weighted sq. distance -> [K,H,W]
match = dist2 < (MATCH_SIGMA * sigma) ** 2 * EFF_CH # 2.5-sigma test; EFF_CH = 0.25+1+1 = 2.25

Broadcasting: frame[None] - mu stretches the single frame against all K layers — numpy repeats it virtually, no copies. einsum multiplies diff·diff elementwise, weights each channel by CH_W and sums over the channel axis c - one weighted squared distance per (k, y, x). The threshold's ·EFF_CH (= 0.25+1+1) is the weighted version of "each channel within 2.5σ": L contributes only a quarter of a channel, so brightness events barely move the distance.

3 · "The matched Gaussian" without a loop: one-hot masks

ks = np.arange(K)[:, None, None]               # [K,1,1]: the numbers 0,1,2,3 as layers
score  = np.where(match, weight / sigma, -1.0) # matching Gaussians compete by omega/sigma
k_best = score.argmax(axis=0)                  # [H,W]: per pixel, WHICH k won
matched_any = match.any(axis=0)                # [H,W]: did anything match at all?
upd = (k_best[None] == ks) & matched_any[None] # bool [K,H,W]: exactly one True per matched pixel

k_best[None] == ks compares the winner map against the constant layers 0..3 → a one-hot cube: for pixel (y,x) only layer k_best(y,x) is True. This cube IS the chapter's match indicator Mk,t — and multiplying/where-ing with it applies an update "only to the matched Gaussian of each pixel", with zero loops.

🎯

Our one addition to the chapter's recipe: Gaussian 0 is initialized from the per-pixel temporal MEDIAN (μ) and MAD (σ) of the whole video — np.median(stack, axis=0). The person covers any pixel for a minority of frames, so the median IS the background. Without this, σ starts at a guess and needs ~400 frames to converge; we have 205. We measured the failure before adding it: legs matched the door through a σ=30-wide window.

5 · The B-set rule as array surgery — worked example

One real pixel (person lingered nearby), T = 0.3. Sort by ω/σ, walk down until the cumulative weight BEFORE the current row reaches T:

rank (by ω/σ)Gaussianωσω/σcum ω before row< T=0.3 ?verdict

2k1 — person's shirt (ghost)0.249.80.0240.62noforeground
3k3 — person's shorts (ghost)0.098.50.0110.86noforeground
4k2 — noise junk0.0510.00.0050.95noforeground
 
order    = np.argsort(-(weight / sigma), axis=0)      # per pixel: k indices best-first
w_sorted = np.take_along_axis(weight, order, axis=0)   # weights rearranged into that order
cum      = np.cumsum(w_sorted, axis=0)                 # running total down the ranks
in_bg_sorted = (cum - w_sorted) < T_BG                 # "cum BEFORE this row" - the argmin-b rule
np.put_along_axis(is_bg, order, in_bg_sorted, axis=0)  # scatter verdicts back to original k slots

cum - w_sorted is the cumulative weight of all BETTER-ranked Gaussians: the row is background exactly if the set wasn't already full when we reached it — a vectorized "take from the top until Σω > T". put_along_axis undoes the sort so is_bg[k,y,x] lines up with the original arrays. With T = 0.3 and the median-mode holding ω ≈ 0.6+, in practice only the true background mode qualifies — the person's ghost modes never do.

6 · Classification + the shadow veto

background = (match & is_bg).any(axis=0)   # matched SOME Gaussian that is IN the B-set

# cast shadow in Lab: luminance attenuated, chroma nearly unchanged
l_ratio = frame[..., 0] / np.maximum(bg_mean[..., 0], 1.0)  # L / background L
chroma_close = ((np.abs(frame[..., 1] - bg_mean[..., 1]) < 8) &
                (np.abs(frame[..., 2] - bg_mean[..., 2]) < 8)) # a, b stay put
shadow = (l_ratio > 0.50) & (l_ratio < 0.96) & chroma_close
background |= shadow                        # darker-but-same-chroma = shadow, not person
return (~background).astype(np.uint8)       # foreground mask {0,1}

In Lab this test is literal physics: a cast shadow drops L (to 50-96% of the background's L) while leaving the surface's chroma (a, b) within sensor noise (<8 units). The person's skin/clothes shift a/b by tens of units → never mistaken for shadow. This replaced an earlier BGR ratio-uniformity heuristic that a shadow on the blue poster defeated — see the colour-space section above.

7 · Mask cleanup — geometry, not statistics

# specks die, small gaps seal (ellipse kernels, half-res pixels)
mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN,  OPEN_KERNEL)   # erode->dilate, 5x5
mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, CLOSE_KERNEL)  # dilate->erode, 13x13

# keep every blob at least 20% of the biggest (torso may split from legs
# at dark clothing), then close again to fuse the kept pieces
n, labels, stats, _ = cv2.connectedComponentsWithStats(mask, connectivity=8)
keep = 1 + np.where(areas >= 0.2 * areas.max())[0]
mask = np.isin(labels, keep).astype(np.uint8)

# hole filling: connected-components of the INVERSE mask; any black region
# NOT touching the image border is enclosed by the person -> make it person
n_i, labels_i = cv2.connectedComponents(inv, connectivity=4)
border_labels = np.unique(...)              # labels seen on the 4 image edges
holes = inv & ~np.isin(labels_i, border_labels)
mask[holes] = 1

The hole-fill trick: the background is one giant black region touching the border; a "hole" (gap between arm and body misclassified as background) is a black island that does NOT reach any border. Label the black regions, keep the ones missing from the border list, paint them white.

8 · Boundary smoothing - from half-res blocks to an organic edge

# the mask was decided at half resolution; upscale it SMOOTHLY:
mask_full = cv2.resize(mask.astype(np.float32), (w_full, h),
                       interpolation=cv2.INTER_LINEAR)  # soft 0..1 edge, no 2px staircase
mask_full = ((mask_full > 0.5) * 255).astype(np.uint8)  # re-binarize at the halfway level
mask_full = cv2.medianBlur(mask_full, 9)                # rounds residual jaggies organically
mask_full = cv2.erode(mask_full, np.ones((3, 3), np.uint8)) # pull edge ~1px in: cancels close-kernel bloat
mask_full = (mask_full > 127).astype(np.uint8)

NEAREST upscaling doubles every half-res pixel into a blocky staircase contour (it was visible in the extracted video). LINEAR + threshold traces the 0.5-level curve between blocks - an antialiased boundary. The median filter is the same trick the reference solution uses for its silky edges; the single erode compensates the close-kernel's outward bloat so the edge hugs the person.

9 · The full flow in background_subtraction()

Model trained once on the half-res Lab video; the per-frame loop only classifies. The linear-upscale + threshold + median chain produces the smooth full-res boundary.
Implementation plan

How this becomes our code

Two departures from the surveillance setting, both in our favour: the video is offline (all frames available), and stage 1 already froze the background.

🚀

Vectorize, never loop pixels

State = arrays mu[K,H,W], sigma[K,H,W], w[K,H,W]. Per frame: broadcast the match test for all K at once, apply all updates with boolean masks (np.where). Python loops only over frames.

🔁

Two passes — offline luxury

Pass 1 feeds every frame to the model (it converges without needing to output anything). Pass 2 classifies each frame against the finished model. No "delay" problem, and the person never gets absorbed into the background.

🌗

Shadow handling

The person's shadow moves with him and fails the match test → false foreground → ruins matting. Fix: a matched-but-darker test — if the value is a scaled-down version of the background mean (similar chroma, lower brightness), call it background.

🧹

Mask post-processing

Raw GMM mask = person + specks + holes. Morphological open (kill specks) → close (seal gaps) → keep the largest connected component (there is exactly one person) → fill holes. Then write both outputs.
